<h1 align="center">篇篇 · Pianpian</h1>

<p align="center">
  英語論文の原文を読みながら、内容を理解し、関連文献を探し、中国語の読書ノートを作る。
</p>

篇篇は、英語論文を読む中国語話者向けのデスクトップアプリです。**元の PDF をそのまま閲覧画面に使い**、レイアウト、図表、数式を保持します。段落ごとの読解を支援し、原本、読書位置、単語帳、分析キャッシュをローカルに保存します。

現在のバージョン：`0.4.2` · 主な配布対象：`Windows x64` · 技術構成：`Electron / React / TypeScript`

> 言語の切り替えはリポジトリ紹介文の翻訳です。アプリの画面と読解支援の出力は、現在、中国語を中心としています。

## 最近の更新

- **対話から論文を検索して取り込む**：研究アシスタントは arXiv と Crossref を検索します。確認後、arXiv の公式 PDF をローカルライブラリに保存し、MinerU の解析を開始します。
- **篇篇になりました**：製品と読書パートナーの名前を統一し、gpt-image-2 で生成した折り目のある紙のキャラクターを採用しました。ライブラリから「问问篇篇」、論文の横から「聊聊」、段落の語彙は「篇篇选词」で利用できます。
- **読書のための余白を確保**：会話履歴、新規会話、読書フローを一つのツールバーにまとめ、必要なときだけパネルを開きます。書誌情報の編集画面でグループを直接作成・選択できます。
- **長い論文の起動を改善**：PDF ページを必要時に読み込みます。研究セッションは初めて開いたときに開始し、Pi はワーカースレッドで実行します。
- **ツールの進捗を見やすく表示**：簡潔なタイムラインに状態、タスクの概要、検索結果を表示します。詳細は展開でき、ライブラリへの追加には確認が必要です。
- **引用から原文へ移動**：回答中の引用をクリックすると、対応する PDF ページと読書ブロックへ移動します。
- **段落ごとの語彙生成**：ダブルクリックで翻訳、解説、要約と文脈上の役割、AI 選定語彙を並行生成します。生成前は空の状態を表示し、保存した語彙には例文と出典を残します。

## 主な機能

| 読書の目的 | 現在の機能 |
| --- | --- |
| 論文の体裁を保つ | 連続スクロール、ページ移動、拡大縮小、目次からの移動。段落・図表・数式の領域を PDF に合わせ、複数ページにまたがる段落にも対応します。長い論文では全体のスクロール位置を保ちながら、表示領域付近の PDF ページだけを必要時に読み込みます。 |
| 段落や文を理解する | 中国語の翻訳、解説、要約と文脈上の役割。原文の選択、ストリーミング表示、ローカルキャッシュに対応します。 |
| 図表と数式を読む | 図表をダブルクリックすると、画像と文脈に基づく解説が始まります。回答は生成中から Markdown として表示し、訳文中の数式も数式として表示します。 |
| 学術表現を学ぶ | 段落をダブルクリックするか、手動で AI 選定語彙を生成します。生成前には語彙カードを表示せず、現在の段落に根拠がある語彙のみを表示します。単語帳に意味、例文、原文へのリンクを保存します。 |
| 論文を起点に研究する | Pi による複数ターンの対話。現在の論文の読解、回答中の引用から原文ブロックへの移動、ローカルライブラリと Crossref の検索、簡潔なツール進捗表示、確認後の書誌情報の追加に対応します。 |
| 読書ノートを作る | 中国語の Markdown 草稿を生成し、確認後に保存先を選んで書き出します。精読、文献検索と選別、文献比較とノート作成の三つの研究フローを用意しています。 |
| 文献を管理する | インポート、検索、お気に入り、グループ、書誌情報の編集と削除、読書位置の保存。 |
| 読書環境を調整する | ライブラリのサイドバーとリーダーのツールバーから明色・暗色を切り替え、再起動後も設定を保持します。PDF・図表・数式画像は元の見た目を保ちます。 |

### 篇篇と話す

ライブラリから独立した研究ワークスペースを開くか、現在の論文の横で「**聊聊**」（篇篇と対話）を選びます。続けて質問し、関連論文を検索し、ライブラリへの追加を確認して、読書ノートを生成できます。付属の研究 Skill は必要時に読み込みます。ツールの状態、結果、ページ引用、回答を同じタイムラインに表示します。生成中に過去のメッセージへスクロールすると位置を保持し、最下部へ戻るか新しい質問を送ると自動追従を再開します。

回答中の引用をクリックすると、対応する PDF ページを読み込み、原文の段落へ移動します。引用には読解ツールが実際に返した安定したブロック ID を使い、ページ番号から位置を推測しません。PDF を開くだけでは研究セッションを開始せず、研究タブを初めて開いたときにワーカースレッドで Pi を初期化します。

例えば、次の三つの質問を続けて送れます。

1. 「この論文の手法と主な結論を、原文の引用付きで要約してください。」
2. 「関連論文を二つ探し、タイトル、年、DOI を挙げてください。」
3. 「論文と検索結果から、中国語の読書ノート草稿を作成してください。」

文献検索には現在、**Crossref の公開学術メタデータ**を使用し、検索範囲は同サービスに依存します。候補の追加で保存するのは書誌情報です。全文を読むには PDF をインポートし、MinerU の解析を完了する必要があります。文書の出力形式は Markdown です。ライブラリ全体と論文ごとの会話を別々にローカル保存し、復元・検索・改名・削除できます。長い論文ではモデルに渡す文脈の長さに制限があります。

## 読書の流れ

![原本を保存し、MinerU で準備を終え、原文を読み、必要時に AI 分析を依頼](docs/assets/workflow.svg)

1. **原本を保存**：PDF をインポートし、デスクトップのユーザーデータ領域に保存します。
2. **読書の準備**：MinerU を設定済みなら、自動で PDF をアップロードして解析します。未設定なら原本を保存して設定を案内します。アップロード、待機、解析、結果のダウンロードをライブラリで確認できます。
3. **原文を開く**：解析結果、図表素材、すべての読書領域の座標が揃ってから閲覧を許可します。失敗した処理はライブラリで再試行できます。
4. **必要時に分析**：モデル呼び出しはユーザーの操作で始まります。インポート、解析完了、再起動後の復元では AI 分析を自動実行しません。モデルが失敗しても、準備済みの論文は読めます。

閲覧画面は、まず論文全体の軽量なページ枠を作成し、最初のページと表示領域付近のページを読み込みます。同時に読み込むページは最大三つとし、移動先を優先します。スクロールやページ移動の際に対象ページを追加で読み込み、長い論文の起動や連続したページ移動でリクエストが大量に蓄積することを防ぎます。

## はじめる

### ソースから実行

Git、**Node.js 24.x**、npm を用意し、このリポジトリへのアクセス権を確認してください。

```powershell
git clone https://github.com/yuanshane76-lang/pianpian.git
cd pianpian
npm ci
npm run desktop:dev
```

起動後、「**服务配置**」（サービス設定）で二つの独立したサービスを設定します。**論文解析サービス**には自分の **MinerU Token** を入力します。**モデルサービス**では **DeepSeek 公式サービス**または**阿里雲百錬（Alibaba Cloud Bailian）**を選び、対応する API キーとモデルを設定します。研究対話も同じモデル設定を使用します。[設定ガイド（中国語）](docs/服务密钥配置.md)を参照してください。

Web プレビューには `npm run dev` を使い、`http://127.0.0.1:4173/` を開きます。プレビューでもインポートした PDF をブラウザの保存領域に保持します。デスクトップ版は原本をユーザーデータ領域のファイルとして保存します。システムの安全な認証情報保存と実サービスへのリクエストにはデスクトップ版が必要です。

### Windows インストーラーと ZIP を作成

```powershell
npm run make:win
```

品質チェックの後、Windows x64 のインストーラーと ZIP を生成します：

```text
out/installer/Pianpian-Setup-0.4.2-x64.exe
out/installer/Pianpian-0.4.2-x64.zip
```

インストーラーはアプリ内更新に対応しています。ポータブル版は ZIP の**ディレクトリ全体**を展開して `Pianpian.exe` を起動します。利用者の PC に Node.js は不要です。商用コード署名証明書は使用していないため、Windows の警告が表示される場合があります。利用者は自分のサービス認証情報を設定します。

## データと外部サービス

ローカル優先とは、原本と読書データを PC に保存することです。解析と AI 分析には外部サービスとネットワーク接続を使い、利用枠の消費や料金が発生する場合があります。

| データ・操作 | 保存先と送信範囲 |
| --- | --- |
| 原本 PDF、解析結果、図表素材 | Electron のユーザーデータ領域に保存。MinerU 設定後は、インポートした PDF を自動で MinerU に送信して解析します。 |
| 文献索引、読書位置、単語帳、分析キャッシュ | ローカル保存。キャッシュは内容の署名とサービス設定で識別します。 |
| 翻訳、解説、語彙、図表の解説、質問応答 | ユーザー操作後、必要な段落、文脈、画像、本文を選択したモデル提供者に送信します。 |
| Agent の文献検索とノート草稿 | 検索語を Crossref に送信し、研究タスクに必要な現在の論文とローカルの書誌情報をモデルに渡します。ライブラリへの追加には確認が必要で、草稿はユーザーが保存先を選んだ後に保存します。 |
| サービス認証情報 | 各利用者が設定。Electron のメインプロセスでシステムの安全な保存機能を使って暗号化し、保存済みのキーを平文で画面に返しません。 |
| リポジトリと配布物 | 既定の論文、ユーザーの文献ライブラリ、解析キャッシュ、デモ用の認証情報を含みません。 |

文献を削除すると、その原本、解析素材、分析キャッシュも削除します。自分で単語帳に保存した語彙と例文は残り、出典が利用できない場合は原文への移動を提供しません。

## 開発と検証

```powershell
npm run check
```

一般的な認証情報の形式と現在のブランチ履歴を検査し、自動テスト、TypeScript チェック、フロントエンドのビルドを実行します。GitHub の [Quality checks (Windows)](https://github.com/yuanshane76-lang/pianpian/actions/workflows/quality.yml) も同じコマンドを使い、実際のモデルや MinerU は呼び出しません。

長い PDF 画布を変更した場合は、起動時の描画が表示領域付近に限られること、ページ移動時に対象ページが必要時に読み込まれること、座標判定・目次からの移動・拡大縮小の基準位置が維持されることも確認します。

### デスクトップ検証を再実行する

解析済みの DEER（45 ページ）と FINDEEPRESEARCH（25 ページ）をローカルに用意すると、次のスクリプトで一時ユーザー環境にコピーして応答性と画像を記録できます。正式なライブラリは変更しません。

```powershell
npm run test:reader-performance:e2e
# 設定済みの実サービスで段落生成と三ターンの対話を検証
node scripts/reader-performance-e2e.cjs --live-ai
# 追加の再解析検証入口。未合格で、MinerU の利用枠を消費します
node scripts/reader-performance-e2e.cjs --live-ai --reparse
```

レポートと画像は Git の対象外である `out/reader-performance-acceptance/` または `out/reader-live-acceptance/` に保存します。`npm run test:research-agent:e2e` と `npm run test:paragraph-vocabulary:e2e` は合成データを使い、外部サービスを呼び出しません。

| ディレクトリ | 役割 |
| --- | --- |
| `src/domain/` | 読書ブロック、座標判定、内容署名、キャッシュ、語彙の規則 |
| `src/services/` | PDF.js、保存先へのアクセス、サービス接続 |
| `src/features/`、`src/app/` | 中国語の画面、操作、状態表示 |
| `electron/` | 安全な IPC、認証情報、文書保存、MinerU タスク、モデル呼び出し |
| `tests/`、`scripts/` | 自動テスト、検証、ビルドツール |

タスクごとのブランチと PR で変更を進め、コミット前にステージした差分を確認します。デスクトップ操作、パッケージ作成、有料サービスの実検証は別々に報告します。模擬応答だけでは実サービスの成功を証明できません。
