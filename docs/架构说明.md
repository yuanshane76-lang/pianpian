# 纸研工作台架构

## 产品边界

纸研工作台是一款 Windows 本地优先的英文论文辅助阅读工具，当前完整流程为：

1. 导入 PDF 并保存原始文件；
2. 留在文献库，按论文显示上传、排队、解析和结果下载进度；
3. 已配置 MinerU 时自动上传并调用 v4 解析；未配置时保存原件、提供配置入口，配置后自动继续；
4. 解析结果及资产保存完成，且所有阅读块坐标有效后解锁「打开阅读」；
5. 在 PDF 原始排版上单击段落仅选择，双击段落自动启动完整自然段分析；划选句子时仅分析实际选中内容；
6. 双击后并行生成中文译文、解释、摘要与上下文作用，在独立页签展示流式结果；
7. 双击时同时让 AI 精选本段术语、学术搭配和论证表达，不需再次点击生成；单击仍能先查看本地识别的段落词汇；
8. 用户主动将词汇加入个人单词表，跨论文查看、搜索、标记掌握状态、移除和定位来源；
9. 按需生成全文问答，不提供全文概览模块；
10. 保存阅读位置、解析任务、原始文件、解析结果、图表资源、个人单词表和 AI 缓存。

PDF 原始画布是唯一阅读面。按 2026-10-11 的产品要求，MinerU 完成解析与坐标准备是进入阅读器的强制条件。原件在本机保留，解析失败在文献库重试；AI 分析依旧按需执行，模型配置或模型失败不影响已就绪论文的阅读。界面不凭文本顺序猜测纸面位置。

## 分层

```text
React 界面
  -> 文献库、统一 PDF 阅读器、MinerU 交互层、研究助手、词汇面板
  -> 阅读块、句子选择、词汇识别、分析缓存领域规则
  -> PDF.js 基础解析、本地索引、原件访问适配
  -> Electron preload 安全桥接
  -> 主进程文档存储、MinerU 任务编排、模型调用、密钥存储
  -> MinerU v4 / DeepSeek 或阿里云百炼
```

- `src/domain/`：论文、阅读块、阅读目标、结构化 AI 响应和学术词汇规则；
- `src/services/`：PDF.js、原件读写桥接、本地索引和分析调用边界；
- `src/domain/pdfLayout.ts`：归一化坐标校验和最小包含区域命中规则；
- `src/domain/wordbook.ts`：用户收藏词汇的规范化身份、去重、来源及持久数据校验；
- `src/services/wordbook.ts`：个人单词表本地读写，读取损坏不覆盖原数据，写入失败不显示收藏成功；
- `src/services/pdfTextLayer.ts`：PDF.js 原生透明文本层，支持原文划选；
- `src/features/`：中文界面、渐进加载、阅读视图和研究助手；
- `electron/document-store.cjs`：按 PDF SHA-256 保存原件、解析 JSON、任务 JSON 和图表资产；
- `electron/document-tasks.cjs`：MinerU 上传、轮询、下载、持久化顺序、断点恢复和并发去重；
- `electron/mineru.cjs`：MinerU v4 请求、ZIP 安全解包和结果规范化；
- `electron/ai.cjs`：DeepSeek/百炼兼容模型请求、结构化阅读指南和段落分析；
- `electron/secret-store.cjs`：使用 Electron `safeStorage` 加密密钥；
- `electron/preload.cjs`：白名单 IPC 通道，不向渲染层暴露密钥。
- `electron/research-agent-runtime.cjs`：研究助手会话、工具执行、审批等待和取消生命周期；
- `electron/research-agent-tools.cjs`：当前论文、本地文献库、Crossref 和 Markdown 草稿工具；
- `electron/pi-agent.cjs`：Pi SDK provider、内存凭据、受限 custom tools 和事件转换；
- `src/services/researchAgentProtocol.ts`：跨 IPC 的 Agent 事件协议与长度校验；
- `src/features/reader/ResearchAssistant.tsx`：研究工作区和阅读器内的中文工具时间线。

研究助手使用 Pi SDK 的内存会话，只注册纸研的五个工具。未配置模型时不创建会话，界面引导用户配置服务；Pi 不扫描本机 Skills、扩展、认证或会话目录。公开检索首版返回 Crossref 元数据，收藏条目使用 `recordType: reference`，不能作为已解析 PDF 打开。收藏需要用户确认并复用本地文献库存储；文档导出经过原生保存对话框，Agent 不决定文件路径。论文引用沿用稳定阅读块 ID，跳回原始 PDF。当前助手历史仅在页面内存中保留。

## 数据与一致性

- 原始 PDF 用 SHA-256 作为文档 ID，重复导入不会覆盖原件；
- 阅读块中的 `headingLevel` 只作为目录展示层级；MinerU `text_level`、Markdown 标题深度和本地编号标题在各自解析边界归一化，缺少该字段的旧块按标题文本回退推断，不改变既有块 ID；
- `parse.json` 只在所有图表资产写入成功后发布；
- `task.json` 只有在对应批次的解析结果持久化后才写入 `resultBatchId` 和 `done`；
- 旧批次的解析结果不会被当作新批次结果返回；
- MinerU 下载中断后保留 ZIP 地址，重试不会重新上传并重复消耗额度；
- AI 结果绑定论文正文签名、段落内容签名和模型配置版本；
- 段落 ID 不包含坐标；补坐标时保留已有块 ID，不重置译文缓存；
- MinerU hosted v1 的 0-1000 左上角坐标只在主进程转换一次为 0-1；
- 密钥只在主进程读取，不进入前端状态、日志、论文索引或压缩包。
- `vocabulary` 操作只向主进程和模型发送完整当前段落，不发送全文或邻段；划选句子不缩减词汇来源段落；
- 段落词汇缓存绑定文档 ID、段落内容签名、词汇协议版本和服务配置，旧全文 `guide` 缓存不作为段落词汇使用；
- 个人单词表只由用户主动收藏产生，保存在 `zhiyan-workbench.wordbook.v1`。同词合并但保留不同论文与内容签名的原句来源，不随论文删除而丢失；
- 单词表定位优先匹配当前解析数据的内容签名，解析变化或论文删除后保留原句并将原文入口标为不可用；
- 解释和问答经 React Markdown / GFM 渲染，不执行原始 HTML、不加载模型给出的远程图片、不启用模型生成的链接；
- 摘要与作用、图表解读使用部分 JSON 解析逐步展示已收到的字段；只有严格验证过的完整 JSON 才能进入缓存。段落分析、图表和词汇使用流式输出，DeepSeek `thinking: { type: "disabled" }`、百炼 `enable_thinking: false`。
- 段落双击请求组独立管理 `translate`、`explain`、`insight` 和 `vocabulary` 的输出及状态。单项失败不取消其他项；切换段落、服务或论文时取消整个请求组并丢弃晚到结果。重复双击复用进行中的请求和已完成缓存，只重试缺失或校验失败的结果。
- 单独生成和双击生成统一通过 `src/domain/analysis.ts` 构建缓存身份。词汇响应中的 `overview` 仅表示本段学习重点，不是全文概览；已移除全文 `overview` 请求和界面。

## 冷启动策略

导入后先保存原件并留在文献库，配置完整时自动启动 MinerU。导入、MinerU 完成和重启恢复均不触发模型分析，也不维护后台翻译队列。应用重启时：

- 主进程从 `task.json` 发现所有论文的活动批次，前端自动继续轮询，不依赖当前选中的论文；
- 没有任务的待解析导入会在配置完成后继续，未开始的旧记录可在文献库手动启动；
- 下载中断时从已保存的 ZIP 地址继续；
- 只有当前批次已完成并发布的结构化结果才可解锁；`src/domain/pipeline.ts` 统一检查原件身份、完成状态和所有块的有效坐标，不能仅信任本地索引的 `parseStatus`；
- 老版本结果缺少坐标时，从原有已完成批次恢复结果，不重新上传论文；
- 翻译、解释、摘要与作用、图表解读、词汇精选和问答都由用户主动触发，保留流式输出、切换取消和结果缓存；
- 状态条分别展示“原文阅读”和“段落定位”，区分排队、页面解析、结果转换和下载，只有服务提供页面进度时显示百分比；不再显示“中文预览”、后台翻译计数或暂停、继续入口；
- 定位就绪提示可关闭，4 秒后自动消失；下载失败重试已有批次。PUT 上传成功后的检测延迟保留为排队状态，主进程持久化 `uploadCompletedAt`，两分钟仍未接收文件才提示重传，避免立即误判失败；
- 已有分析缓存和用户数据不因移除自动翻译而清空。

## 跨页自然段坐标

MinerU 的 `content_list.json` 可能将跨页正文合并为一个段落，却仅保留起始页的 `bbox`。解析适配层读取同包 `layout.json`（或 `*_middle.json`），用起始页的原始区域关联自然段，通过 `cross_page` 行与后续页 `preproc_blocks` 的精确内容和原始坐标匹配恢复续段。布局坐标按该页 `page_size` 转为 0–1，不能按文本顺序猜测页码或位置。无法唯一确认续段来源时拒绝发布完整结果。

`DocumentBlock.pageBounds` 包含同一自然段的所有页码和区域，`pageNumber`、正文和段落 ID 继续代表规范自然段。`src/domain/pdfLayout.ts` 统一校验多页坐标并生成仅用于绘制的页面投影；组件将点击、双击和划选映射回规范段落，另传实际交互页码，投影不进入缓存或全文上下文。续页 DOM ID 唯一，重开时按保存页码定位对应区域。

几何协议版本为 `layoutVersion: 2`。旧结果从已经完成的批次 ZIP 恢复，不重新上传 PDF，并保留已有块 ID 和正文；下载失败保留原有解析结果。

## 阅读交互生命周期

PDF 画布、透明文本层、透明识别框共用精确页面尺寸。屏幕像素密度只影响画布清晰度，不进入识别框的位置计算。适应宽度监听实际滚动区，收起目录或助手后自动重算；翻页或重绘期间禁用命中，避免上一页画面被当作下一页内容。

目录和词汇跳转先切换目标页，再等待页面绘制和识别框挂载，最后滚动至目标；阅读位置由实际 PDF 滚动区保存。双击使用可靠坐标命中的完整自然段，并清除双击产生的单词选择。划选句子以纸面坐标确认所属块，直接传递选中的 PDF 原文，不要求与 MinerU 的空格、引用编号逐字一致。

没有完整可靠坐标时保持文献库阅读入口锁定，并显示解析错误或重试入口，不产生假识别框。扫描 PDF 没有原生文本层时仍可点击已定位段落，原文划句能力取决于 PDF 是否带文本层。

## 安全边界

- MinerU API Key 和模型 API Key 使用系统安全存储；
- 远端模型调用只接受固定官方端点；
- MinerU 上传地址和结果地址使用 HTTPS 主机白名单；
- ZIP 解包防止路径穿越、符号链接、大小炸弹、CRC 错误和重复路径；
- PDF、解析结果、任务和资产均有大小上限；
- 原始 PDF 保存在本机；文献库说明导入会自动上传到 MinerU 并使用账号额度，密钥只由主进程读取。
