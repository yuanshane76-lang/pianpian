# 篇篇架构

## 产品边界

篇篇是一款 Windows 本地优先的英文论文辅助阅读工具，当前完整流程为：

1. 导入 PDF 并保存原始文件；
2. 留在文献库，按论文显示上传、排队、解析和结果下载进度；
3. 已配置 MinerU 时自动上传并调用 v4 解析；未配置时保存原件、提供配置入口，配置后自动继续；
4. 解析结果及资产保存完成，且所有阅读块坐标有效后解锁「打开阅读」；
5. 在 PDF 原始排版上单击段落仅选择，双击段落自动启动完整自然段分析；划选句子时仅分析实际选中内容；
6. 双击后并行生成中文译文、解释、摘要与上下文作用，在独立页签展示流式结果；段落理解区域可开启“祖母模式”，让后续段落结果使用极通俗的中文；
7. 双击时同时让 AI 精选本段术语、学术搭配和论证表达，不需再次点击生成；单击只选择段落，生成前不展示本地预填词汇；
8. 用户主动将词汇加入个人单词表，跨论文查看、搜索、标记掌握状态、移除和定位来源；
9. 按需生成全文问答，不提供全文概览模块；
10. 保存阅读位置、解析任务、原始文件、解析结果、图表资源、个人单词表和 AI 缓存。

PDF 原始画布是唯一阅读面。按 2026-10-11 的产品要求，MinerU 完成解析与坐标准备是进入阅读器的强制条件。原件在本机保留，解析失败在文献库重试；AI 分析依旧按需执行，模型配置或模型失败不影响已就绪论文的阅读。界面不凭文本顺序猜测纸面位置。

## 分层

```text
React 界面
  -> 文献库、统一 PDF 阅读器、MinerU 交互层、研究助手、词汇面板
  -> 阅读块、句子选择、词汇识别、分析缓存领域规则
  -> PDF.js 基础解析、本地索引、原件访问适配
  -> Electron preload 安全桥接
  -> 主进程文档存储、MinerU 任务编排、模型调用、密钥存储
  -> MinerU v4 / DeepSeek 或阿里云百炼
```

- `src/domain/`：论文、阅读块、阅读目标、结构化 AI 响应和学术词汇规则；
- `src/services/`：PDF.js、原件读写桥接、本地索引和分析调用边界；
- `src/domain/pdfLayout.ts`：归一化坐标校验和最小包含区域命中规则；
- `src/domain/wordbook.ts`：用户收藏词汇的规范化身份、去重、来源及持久数据校验；
- `src/services/wordbook.ts`：个人单词表本地读写，读取损坏不覆盖原数据，写入失败不显示收藏成功；
- `src/services/pdfTextLayer.ts`：PDF.js 原生透明文本层，支持原文划选；
- `src/features/`：中文界面、渐进加载、阅读视图和研究助手；
- `electron/document-store.cjs`：按 PDF SHA-256 保存原件、解析 JSON、任务 JSON 和图表资产；
- `electron/document-tasks.cjs`：MinerU 上传、轮询、下载、持久化顺序、断点恢复和并发去重；
- `electron/mineru.cjs`：MinerU v4 请求、ZIP 安全解包和结果规范化；
- `electron/ai.cjs`：DeepSeek/百炼兼容模型请求、结构化阅读指南、段落分析、图表解读、公式解读和论文知识库（论证主线、章节条目）提取；
- `electron/secret-store.cjs`：使用 Electron `safeStorage` 加密密钥；
- `electron/preload.cjs`：白名单 IPC 通道，不向渲染层暴露密钥。
- `electron/research-agent-runtime.cjs`：研究助手会话、工具执行、审批等待和取消生命周期；
- `electron/research-agent-tools.cjs`：当前论文、本地文献库、arXiv/Crossref、按服务启用的联网工具、确认入库和 Markdown 草稿工具；
- `electron/deepseek-web.cjs`：DeepSeek 官方 Search/Fetch 原生 API 适配、响应规范化、网页地址校验和结果大小限制；
- `electron/semantic-scholar.cjs`：Semantic Scholar 相似论文检索适配，限制官方 API 主机、序列化请求、处理限流重试并缓存种子结果；
- `src/domain/paperRadar.ts` 与 `src/services/paperRadar.ts`：相似论文元数据规范化、去重、排除当前论文/本地已有文献及桌面 IPC 调用；
- `src/features/reader/PaperRadar.tsx`：阅读器内懒加载的相似论文面板；仅展示公开元数据和原文入口，不下载全文；
- `src/domain/paperWiki.ts`：单论文知识库（wiki-lite）的领域规则——正文按真实一级章节合并为少数大部分（过滤参考文献等尾部材料、过小的块并入邻块、总量封顶），各部分两级语义要点树解析、装配结果（部分语义标题 + 论证主线）解析、锚点校验、近似重复条目本地合并、覆盖率统计和按部分缓存身份；
- `src/domain/outlineMap.ts`：投影层，把大块划分 + 装配结果 + 要点树组装成思维导图（论证主线分支 + 各语义部分分支，支撑点挂要点之下）；
- `src/features/reader/OutlineTree.tsx` 与 `OutlineDrawer.tsx`：d3-hierarchy 计算左右展开的树布局，React 渲染 SVG，d3-zoom 处理平移与缩放；整棵树一次性铺开，默认收起支撑点、可展开全部/收起支撑点，部分节点带生成中/失败状态与生成进度；右侧抽屉覆盖助手面板但保留左侧原文可见；
- `electron/arxiv-pdf-download.cjs`：arXiv 官方 PDF 的限域请求、120 秒总超时、100 MB 流式上限及内容校验；
- `electron/literature-imports.cjs`：主进程导入占用及完成回执；与手动原件保存、删除共用队列，确保取消清理完成后才允许后续导入复用文件；
- `electron/pi-agent.cjs`：Pi SDK provider、内存凭据、受限 custom tools 和事件转换；
- `src/services/researchAgentProtocol.ts`：跨 IPC 的 Agent 事件协议与长度校验；
- `src/features/reader/ResearchAssistant.tsx`：研究工作区和阅读器内的中文工具时间线。

研究助手使用 Pi SDK 的内存运行会话，默认注册六个本地研究工具；当前服务为 DeepSeek 时额外注册 `search_web` 与 `fetch_web_page`，直接调用主进程中的官方 Search/Fetch API，百炼会话不声明这两个工具。未配置模型时不创建模型会话，界面引导用户配置服务，但仍可管理本地历史；Pi 只按清单加载随应用分发的研究 Skill，不扫描个人 Skills、扩展、认证或会话目录。公开检索并行查询 arXiv Atom API 与 Crossref，分别标记不可用来源并将精确标题匹配排前；DeepSeek 联网搜索和网页正文只作为待分析资料，结果经过字段白名单、HTTP/HTTPS 地址校验和大小限制后再进入模型上下文，工具失败不伪造来源。只有当前会话真实检索返回的候选 ID 可以申请入库。arXiv 论文需用户确认后由 Electron 限域下载、校验 PDF 并通过本地文档库持久化，随后创建/升级为含 `originalId` 的论文条目并接入 MinerU 队列；持久化回执返回前不能报告成功。Crossref 结果仍仅保存为 `recordType: reference` 元数据，不冒充已下载 PDF。收藏需要用户确认并复用本地文献库存储；文档导出经过原生保存对话框，Agent 不决定文件路径。论文引用沿用稳定阅读块 ID，跳回原始 PDF。助手历史由 Electron 本地持久化，运行时按范围恢复。

PDF 入库按原件内容哈希复用；已经存在的 PDF 保留稳定论文 ID、收藏和分组，只有元数据条目时才原地升级。不同内容的 arXiv 版本保留独立原件，不把新版本标识绑定到旧 PDF。手动重复导入同一原件也按 `originalId` 复用记录。停止、离开对话或 Agent 终止会取消尚未落库的导入；渲染进程通过 `zhiyan:literature:finish-import` 释放主进程占用，由主进程清理未保留的新原件。渲染进程失联超过五分钟时保留原件并释放队列，避免误删可能已提交的数据。

## 数据与一致性

- 原始 PDF 用 SHA-256 作为文档 ID，重复导入不会覆盖原件；
- 阅读块中的 `headingLevel` 只作为目录展示层级；MinerU `text_level`、Markdown 标题深度和本地编号标题在各自解析边界归一化，缺少该字段的旧块按标题文本回退推断，不改变既有块 ID；
- `parse.json` 只在所有图表资产写入成功后发布；
- `task.json` 只有在对应批次的解析结果持久化后才写入 `resultBatchId` 和 `done`；
- 旧批次的解析结果不会被当作新批次结果返回；
- MinerU 下载中断后保留 ZIP 地址，重试不会重新上传并重复消耗额度；
- AI 结果绑定论文正文签名、段落内容签名和模型配置版本；
- 段落分析缓存还绑定阅读表达模式；“标准模式”和“祖母模式”不会互相复用结果，切换模式会取消旧请求并按新模式重新生成；
- 段落 ID 不包含坐标；补坐标时保留已有块 ID，不重置译文缓存；
- MinerU hosted v1 的 0-1000 左上角坐标只在主进程转换一次为 0-1；
- 密钥只在主进程读取，不进入前端状态、日志、论文索引或压缩包。
- `vocabulary` 操作只向主进程和模型发送完整当前段落，不发送全文或邻段；划选句子不缩减词汇来源段落；
- 段落词汇缓存绑定文档 ID、段落内容签名、词汇协议版本和服务配置，旧全文 `guide` 缓存不作为段落词汇使用；
- 个人单词表只由用户主动收藏产生，保存在 `zhiyan-workbench.wordbook.v1`。同词合并但保留不同论文与内容签名的原句来源，不随论文删除而丢失；
- 单词表定位优先匹配当前解析数据的内容签名，解析变化或论文删除后保留原句并将原文入口标为不可用；
- 解释、摘要与作用和问答经共享 React Markdown / GFM 组件渲染；`remark-math` 在 Markdown 解析边界识别 `$…$` 行内公式和 `$$` 多行公式，与翻译共用 KaTeX 的安全渲染设置。未闭合的流式公式、非法 TeX 和需要信任的命令保留原文；代码中的公式不转换，长公式在自身区域内横向滚动。不执行原始 HTML、不加载模型给出的远程图片、不启用模型生成的链接；
- 摘要与作用、图表解读和公式解读使用部分 JSON 解析逐步展示已收到的字段；只有严格验证过的完整 JSON 才能进入缓存。段落分析、图表、公式和词汇使用流式输出，DeepSeek `thinking: { type: "disabled" }`、百炼 `enable_thinking: false`。
- 段落双击请求组独立管理 `translate`、`explain`、`insight` 和 `vocabulary` 的输出及状态。单项失败不取消其他项；切换段落、服务或论文时取消整个请求组并丢弃晚到结果。重复双击复用进行中的请求和已完成缓存，只重试缺失或校验失败的结果。
- 单独生成和双击生成统一通过 `src/domain/analysis.ts` 构建缓存身份。词汇响应中的 `overview` 仅表示本段学习重点，不是全文概览；已移除全文 `overview` 请求和界面。
- 祖母模式只作用于段落翻译、解释、摘要与作用和精选词汇；主进程在固定分析提示词后追加通俗表达要求，不改变原文、结构化字段和模型服务边界。
- 文章架构不做标题树复读机：正文先在 `src/domain/paperWiki.ts` 按真实一级章节合并为少数大部分（无标题退化为单一“全文”块），模型只做两类理解性生成——一次装配调用（`wiki-thread`：为各部分起语义标题并提炼跨部分论证主线）和每部分一次两级要点树（`wiki-part`：要点 → 支撑点，按内容逻辑组织而非段落顺序）。生成一次性完成：装配与全部部分并发提交（限流 3 路），大块骨架立即可见、语义标题与要点陆续挂上、抽屉显示进度。支撑点只允许返回本部分阅读块 ID，页码与引文一律本地解析，越界锚点按幻觉丢弃；近似重复支撑点由本地 lint 合并。装配缓存绑定文档签名，部分缓存绑定部分内容签名，协议版本为 `paper-wiki-v2`，解析失败不写缓存；装配失败不拦截部分要点，单部分失败可单独重试，重新生成为全量强制。部分请求与其他分析并发互不打断。点击节点复用 `sourceNavigation → focusTarget(flash)` 链路定位原文，不另建滚动机制。

## 冷启动策略

桌面端首次读取服务配置后，如果当前模型服务或 MinerU 缺少密钥，先显示不可跳过的配置引导；只保存一项时保持引导并切到另一项，两项都保存成功后才进入工作台。配置读取失败显示重试，不以空配置覆盖已有密钥。浏览器预览不触发该桌面门禁。导入后先保存原件并留在文献库，配置完整时自动启动 MinerU。导入、MinerU 完成和重启恢复均不触发模型分析，也不维护后台翻译队列。应用重启时：

- 主进程从 `task.json` 发现所有论文的活动批次，前端自动继续轮询，不依赖当前选中的论文；
- 没有任务的待解析导入会在配置完成后继续，未开始的旧记录可在文献库手动启动；
- 下载中断时从已保存的 ZIP 地址继续；
- 只有当前批次已完成并发布的结构化结果才可解锁；`src/domain/pipeline.ts` 统一检查原件身份、完成状态和所有块的有效坐标，不能仅信任本地索引的 `parseStatus`；
- 老版本结果缺少坐标时，从原有已完成批次恢复结果，不重新上传论文；
- 翻译、解释、摘要与作用、图表解读、公式解读、词汇精选和问答都由用户主动触发，保留流式输出、切换取消和结果缓存；图表使用本地资产，公式使用 MinerU 提取的公式文本和相邻段落上下文。
- 文献库显示排队、页面解析、结果转换和下载，只有服务提供页面进度时显示百分比。阅读器不再显示永久的“原文阅读 / 段落定位”状态行，PDF 工具栏直接接在顶部导航下方；
- 定位就绪提示可关闭，4 秒后自动消失；下载失败重试已有批次。PUT 上传成功后的检测延迟保留为排队状态，主进程持久化 `uploadCompletedAt`，两分钟仍未接收文件才提示重传，避免立即误判失败；
- 已有分析缓存和用户数据不因移除自动翻译而清空。

## 跨栏与跨页自然段坐标

MinerU 的 `content_list.json` 可能将跨栏或跨页正文合并为一个段落，却仅保留起始区域的 `bbox`。解析适配层读取同包 `layout.json`（或 `*_middle.json`），用起始区域关联自然段；同页超出原区域的行和标记为 `cross_page` 的行，都通过 `preproc_blocks` 的精确内容与原始坐标匹配恢复来源。同页跨栏无需 `cross_page` 标记；每个物理来源区域单独保存，不合成覆盖栏间空白的大框。布局坐标按该页 `page_size` 转为 0–1，不能按文本顺序猜测页码或位置。无法唯一确认续段来源时拒绝发布完整结果。

`DocumentBlock.pageBounds` 包含同一自然段的所有页码和区域，允许同一页拥有多个不同坐标区域；完全重复的区域无效。`pageNumber`、正文和段落 ID 继续代表规范自然段。`src/domain/pdfLayout.ts` 统一校验多页坐标并生成仅用于绘制的页面投影；组件将点击、双击和划选映射回规范段落，另传实际交互页码，投影不进入缓存或全文上下文。所有区域 DOM ID 唯一；同页跨栏的阅读位置额外保存物理区域 ID，重开时按保存页码和区域定位。该区域身份不进入分析请求或缓存。

几何协议版本为 `layoutVersion: 3`。旧结果从已经完成的批次 ZIP 恢复，不重新上传 PDF，并保留已有块 ID 和正文；下载失败保留原有解析结果。

## 阅读交互生命周期

文献库壳固定在当前视口内，文献列表、分组列表和文献详情分别拥有滚动区域；长标题、较多条目或分组不能撑高整个窗口。侧栏的「服务配置」与主题切换入口始终保留在可见区域，窄视口使用带可访问名称和提示的图标入口。主进程根据鼠标所在显示器的可用工作区计算初始窗口尺寸并居中，包含原生边框、标题栏和菜单，不遮挡系统任务栏；正常最小窗口为 980 × 680，工作区更小时按工作区限制。

PDF 画布、透明文本层、透明识别框共用精确页面尺寸。屏幕像素密度只影响画布清晰度，不进入识别框的位置计算。适应宽度监听实际滚动区，收起目录或助手后自动重算；翻页或重绘期间禁用命中，避免上一页画面被当作下一页内容。

长论文先读取第一页并建立轻量页面占位，视口附近及定位目标的页面按需加载。`src/services/pdfPageLoader.ts` 持有每份文档的加载队列，最多同时请求三个页面；当前目标优先，视口变化替换尚未启动的任务，离开需求范围的晚到页面清理后丢弃。切换文档或卸载时停止队列，旧结果不能更新新文档。未访问页暂用第一页尺寸，加载后校正；目录、引用和恢复定位在真实尺寸与目标画布准备完成前持续维护目标位置。

`originalPdf` 合并同一原件同时进行的桌面读取，完成或失败后立即移除请求，不长期缓存字节。PDF 初始化在读取完成后先检查该组件是否仍有效，开发模式 StrictMode 已废弃的效果不能创建第二份 PDF.js 文档或 worker。

目录和词汇跳转先切换目标页，再等待页面绘制和识别框挂载，最后滚动至目标；阅读位置由实际 PDF 滚动区保存。双击使用可靠坐标命中的完整自然段，并清除双击产生的单词选择。双击图片或表格自动解读当前图表，双击公式自动解读当前公式，并分别复用进行中的请求或已验证缓存；切换内容时取消请求并丢弃晚到结果。图表和公式的流式预览与完成态分别共用同一结果区域，不使用内部限高滚动框。划选句子以纸面坐标确认所属块，直接传递选中的 PDF 原文，不要求与 MinerU 的空格、引用编号逐字一致。桌面版还可将当前句子或整段加入当前论文对话：引用由稳定论文标题、页码、段落 ID 和原文组成，追加到输入框并聚焦，不自动发送；引用文本按纯文本处理，不执行其中的 Markdown 或 HTML。

没有完整可靠坐标时保持文献库阅读入口锁定，并显示解析错误或重试入口，不产生假识别框。扫描 PDF 没有原生文本层时仍可点击已定位段落，原文划句能力取决于 PDF 是否带文本层。

## 安全边界

### 应用内更新与数据保留

Windows NSIS 安装版使用 `electron-updater` 检查独立公开 GitHub Releases；下载端点在主进程固定配置，不接受渲染端 URL 或 Token。先由 `latest.yml` 的 SHA-512 校验安装器，再使用固定 Ed25519 公钥验证发布附件签名所绑定的精确版本、安装文件名、长度和 SHA-512。安装版本必须严格递增，不接受降级、测试版本或免安装 ZIP 更新；下载和安装是用户分开的明确操作。

安装前主进程先启用 IPC 写入屏障，确认没有新文档/AI/历史操作，要求渲染进程写入当前文献索引、分组、词汇和分析缓存并逐键回读校验，显式 flush Chromium 存储，排空对话历史。随后在原 `userData` 创建带完成标记的本机备份，内容包括 localStorage 逻辑快照、加密配置、对话历史、解析结果与任务元数据；大体积 PDF 和图表原件留在其原位置不复制。仅全部步骤成功后才允许更新器启动安装器；普通退出也先 flush 历史，flush 失败取消退出。失败恢复旧进程的写入能力并保留旧版。NSIS 用户级安装固定 `appId`/GUID；卸载默认不删除 `%APPDATA%\\纸研工作台`。

备份位于 `update-backups/<id>/`，`backup.json.complete` 只有在所有文件写入且校验摘要登记后才变为 `true`。它不上传，不是 Windows 密钥跨账号迁移，也不重复存放原件。密钥在原用户身份下用系统安全存储；更新不能清空 localStorage 或把用户切换到新的 Chromium origin。旧免安装版本不具备更新能力，用户必须手动安装一次 NSIS 版本；新的免安装 ZIP 也不提供应用内更新。

发布脚本必须先验证稳定语义版本、安装器文件、blockmap 和 ZIP；用仓库外 Ed25519 私钥签名，生成更新摘要与 SHA-256 清单。GitHub Actions 收到发行标签后先验证标签格式，再把仓库 secret 写到 runner 临时文件，CI 的发布 Token 只授权独立发行仓库。正式发布禁止覆盖同版本 Release，不自动公开源码仓库。未执行真实公开发行仓库发布时，不宣称 GitHub 更新源或 CI 发布已经验证。

- MinerU API Key 和模型 API Key 使用系统安全存储；
- 远端模型调用只接受固定官方端点；
- MinerU 上传地址和结果地址使用 HTTPS 主机白名单；
- ZIP 解包防止路径穿越、符号链接、大小炸弹、CRC 错误和重复路径；
- PDF、解析结果、任务和资产均有大小上限；
- 原始 PDF 保存在本机；文献库说明导入会自动上传到 MinerU 并使用账号额度，密钥只由主进程读取。

## 研究助手预置技能与流式阅读

研究助手的 Pi 会话由 Electron 主进程管理。`pi-worker-session.cjs` 在工作线程中加载 Pi SDK、初始化和运行模型会话；产品工具仍在主进程通过受控消息执行，取消信号跨线程传递，关闭会话会停止工具并结束线程。密钥只在主进程与该工作线程之间使用，不进入渲染进程。关闭内置文件与命令工具，只开放论文读取、本地文献检索、arXiv/Crossref 检索、确认入库、Markdown 草稿和预置 Skill 读取六个核心产品工具；DeepSeek 会话按服务能力追加受限的 Search/Fetch 工具。阅读器首次打开研究页签后才挂载会话，切换阅读辅助页签保留当前对话。

单篇与全库助手共享一条紧凑工具栏：当前对话标题兼作历史入口，右侧提供技能与新建操作。历史和技能使用互斥的非模态浮层，不挤压对话区域；点击外部、焦点离开或按 Escape 关闭，选择历史后焦点回到历史入口，选择技能后移到提问框。阅读页签失活时通过 `active` 关闭浮层，保留已有会话与工具执行。运行状态和当前范围位于输入区底部。Markdown 的组件渲染器保持稳定，避免浮层关闭重绘时替换引用按钮、丢失正在进行的点击和焦点。

### 对话历史与范围

- 阅读器右侧使用 `scope: paper`，历史以稳定 `paperId` 隔离，正文工具拒绝其他论文 ID。首页进入研究工作区始终使用 `scope: library`、`paper: null`，不受文献列表的选中项影响。
- `electron/research-conversations.cjs` 在用户目录 `research-history/conversations.json` 保存版本化历史，包括用户/助手消息、流式未完成文本、工具结果、标题和时间。串行写入临时文件后原子替换；文件损坏时保留原文件并报告错误，不以空记录覆盖。上限为 500 个对话、64 MiB；界面提供搜索标题/消息、新建、重命名、二次确认删除和一键恢复。
- 历史 CRUD 与运行会话均经过现有可信主框架 IPC 校验。开始/恢复时主进程根据 `conversationId` 读取历史并核对范围，不接受渲染进程传入的模型历史。事件携带当前对话身份，切换/停止先结束旧运行并刷新持久化，避免晚到事件串入其他对话。流式增量最多合并 200 ms 后落盘；写入失败保留待写队列并显示中文错误，正常退出前等待停止与保存。
- 恢复界面使用完整本地历史；Pi 内存会话通过 SessionManager 注入最近约 6 万字符的用户和助手文本，历史工具和待确认操作不会重放。未完成工具恢复为已中止。模型重新引用事实必须重新读取原文。长会话此前文本仍可在界面查询；切换/重启不会自动调用外部服务，仅发送新问题时请求模型。
- 全库 `search_library` 按关键词检索标题、作者、年份、DOI 与本机已发布解析正文，每篇返回最多 3 个相关段落摘要；当前不是向量语义检索。正文按需通过主进程文档存储读取，要求任务已完成、发布批次一致、布局版本有效；未解析条目仅提供元数据。全文不一次性装入模型上下文。单次会话接受最多 5000 篇文献元数据，超限明确报错，不静默漏检。全库 `read_current_paper` 必须明确传入文献库内的 `paperId`，按关键词/页码限量返回正文。
- 全库引用使用 `[引用:paperId::blockId]` 和协议中的 `referenceId`，运行时证据与渲染端真实论文/块双重校验后，跳转到对应论文的原始 PDF。单篇引用仍兼容原有 `[引用:blockId]`，编号与稳定业务身份分离。

Agent 使用 `[引用:blockId]` 标记原文来源。运行时仅将 `read_current_paper` 已返回的块登记为引用证据，在完成事件中解析标记并输出引用协议；文档或解析内容变化时清空证据。前端 `src/domain/paperCitations.ts` 再确认论文身份与当前块是否存在，只输出合法的稳定块身份。流式阶段用已完成阅读工具的块验证完整标记，完成后使用运行时确认过的引用。

`src/features/reader/markdownCitations.ts` 先验证原文标记，再在已整理脚注位置的实际渲染树中为每条回答分配 `[1]`、`[2]`；同一块重复引用复用序号，代码、链接、未显示脚注和未完成标记不参与编号。`MarkdownContent` 在同一条文本增量追加期间保留已显示的来源编号；即使后续 Markdown 定义改变早先内容的显示方式，仍在显示的引用也不变号，非增量替换则重新编号。不显示来源页码、摘录、工具外附加引用或回答底部的重复引用列表，悬停仅提示“查看原文”。序号不是缓存或定位身份；点击仍传递原始稳定块 ID，阅读器根据当前解析结果加载目标页和坐标区域，短暂高亮约 1.6 秒。恢复阅读位置不触发高亮，减少动态效果偏好下保留静态定位反馈、不播放闪烁动画。Electron 引用协议不变。

工具执行行默认呈现状态、名称与摘要，展开后显示检索候选及调用详情；确认加入和文档保存入口保持可操作。词汇仅在 AI 结果完成后显示有本段原文依据的精选项；双击段落自动请求词汇，生成前为空态，生成中与空结果、错误、缓存状态分开呈现，不展示本地默认词表作为 AI 结果。

`skills/research/` 随应用分发三个研究流程：论文精读、文献检索与筛选、文献对比与笔记。标准 `SKILL.md` 是流程说明的来源；`manifest.json` 只保存登记名称、中文显示名和入口问题。`electron/research-skills.cjs` 按应用相对路径发现和读取这些文件，只接受登记名称，不读取外部技能目录。Pi 先收到技能名称与描述，再通过 `read_research_skill` 按需获取正文；Skill 不会扩大产品工具权限。

只读 `zhiyan:agent:skills` IPC 在未配置模型时也可返回清单；`session_started.skills` 携带相同摘要。前端在 `src/services/researchAgentProtocol.ts` 校验清单、名称、标题与问题长度，界面不维护第二份技能定义。点击技能入口填入问题，由用户发送。文献对比按原文、摘要和元数据区分证据，不把检索条目当作已读全文。

`useConversationScroll` 负责研究对话滚动：流式更新按动画帧合并，使用即时滚动并关闭浏览器滚动锚定，底部跟随时响应内容及容器尺寸变化；用户向上阅读时保持位置，回到底部或发新问题恢复跟随。卸载会清理观察器和待执行动画帧。

## 品牌与数据兼容

产品与 AI 阅读伙伴统一名为「篇篇」。`brand.json` 保存桌面身份与品牌主张；`src/brand/Pianpian.tsx` 消费本地 WebP 素材，统一装饰图与无障碍呈现。图像生成只用于开发期制作素材，不作为应用功能或运行时依赖。

`electron/brand.cjs` 在创建存储前配置桌面身份。默认用户数据仍使用既有「纸研工作台」目录，显式 `--user-data-dir` 或测试已设置的目录不改写；仓库、协议、IPC、本地存储键、文献和缓存身份不改名。打包白名单只包含品牌配置、正式 WebP 与 ICO，不包含开发期提示词、生成中间图、认证文件或用户数据。文案、角色口吻与素材来源见 [品牌语言](品牌语言.md)。
