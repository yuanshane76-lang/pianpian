# 自动更新与 GitHub 发布

## 用户怎么更新

从 0.4.0 起，推荐下载 `Pianpian-Setup-<版本>-x64.exe` 安装。文献库底部「检查更新」与桌面菜单「篇篇 → 检查更新」打开同一个窗口。检查不会自动下载；点击下载后可以继续阅读，下载完成后点击「重启并更新」才安装，不会在普通退出时偷偷安装。

旧 0.3.0 ZIP 没有更新器，需要手动安装一次。0.4.0 ZIP 仍是免安装分发，显示下载安装版的提示，不将自身当作可原地替换的安装版。开发模式不访问更新服务。

## 数据保留与备份

- 应用身份固定为 `com.pianpian.desktop`，NSIS GUID 固定。
- 数据继续使用 `%APPDATA%\纸研工作台`，不随品牌、安装目录或版本改名。正式阅读面保持 `zhiyan://app`，localStorage 的键也不变。
- 更新只替换程序文件；原始 PDF 和图表资产仍在原来的 `documents` 中。卸载器默认不清除用户数据。
- 导入、解析和回答进行中不执行更新；安装前暂停新 IPC 写入，要求前端将内存状态持久化并明确确认，再落盘对话和浏览器存储，最后备份索引、分组、词汇、缓存、主题、对话、加密配置以及解析/任务元数据。
- 备份在用户数据目录 `update-backups/<时间戳-随机ID>/`，`backup.json` 中 `complete: true` 表示完成。PDF 与图表原件不重复复制，避免每次更新复制整个文献库。
- 任何保存、最终退出准备或备份失败都禁止启动安装器；不会把读取失败解释为空文献库。只清理本次失败的不完整备份，不动之前的完整备份。
- 备份仅在本机，可包含论文正文和对话，不能上传到公开 Issue 或 Release。密钥文件保持系统加密状态。
- 备份不是跨电脑密钥迁移包，也不是防磁盘故障的完整 PDF 备份。未来数据结构改变必须新增带版本号的可恢复迁移，禁止直接清空存储键。

人工恢复前先退出所有篇篇实例并保留当前数据目录副本。备份中的 `research-history`、`documents` 元数据、加密设置可恢复至原位置；`local-storage.json` 是逻辑导出，需要在同一正式页面来源下由维护工具逐键恢复，不能直接替换 Chromium LevelDB 文件。不要直接降级已迁移数据结构的版本。

## 无服务器发布架构

客户端从 `update-config.json` 固定指定的公开 GitHub Releases 读取版本，当前为 `yuanshane76-lang/pianpian-releases`。源码仓库可以继续私有。程序不包含 GitHub Token，也不向更新服务发送论文、密钥或对话。

发布附件：`Pianpian-Setup-<版本>-x64.exe`、对应 `.exe.blockmap`、`Pianpian-<版本>-x64.zip`、`latest.yml`、`update-signature.json`、`SHA256SUMS.txt`。

electron-updater 下载时核对 SHA-512。应用额外核对 Ed25519 发布签名，签名绑定版本、固定安装文件名、大小和 SHA-512，下载后与安装前再次核对实际文件。不自动降级、不接收测试版、不提供前端任意更新源。

独立发布签名不等于 Windows Authenticode 商业代码签名。没有商业证书时首次下载/运行仍可能有系统信誉提示。

## 本机发布

```powershell
npm ci
npm run make:win
npm run release:publish
```

`make:win` 执行凭据检查、全量测试、类型检查、前端构建、NSIS/ZIP 打包和签名。产物在 `out/installer`，签名失败不允许正式发布。

发布私钥默认在本机 `%LOCALAPPDATA%\PianpianPublisher\update-signing-private.pem`，也可通过 `PIANPIAN_UPDATE_SIGNING_KEY_FILE` 指定仓库外文件；不要打印、提交或分发。`update-config.json` 仅包含公钥。请离线安全备份私钥，丢失后无法让已分发版本信任新的发布身份；换钥需要先发仍由旧密钥授权的过渡版本。

`release:publish` 使用本机 `gh auth login` 的登录状态，先检查发行仓库公开性和签名，以草稿上传全部文件后转为正式发布。正式版本不覆盖，修复需递增版本。脚本不自动公开源码仓库，也不创建发行仓库。

## CI 发布

`.github/workflows/release.yml` 支持手动构建及推送 `v<版本>` 标签；标签必须与 package.json 一致。正式发布需要仓库 Secrets：

- `PIANPIAN_UPDATE_SIGNING_KEY`：与应用公钥对应的私钥；
- `PIANPIAN_RELEASE_TOKEN`：仅授予指定发行仓库 Contents 写权限的发布凭据。

先校验版本，再将签名文件写入运行器临时目录；结束时删除，不进入产物。请先本机验证，再配置 Secrets；不要把私钥或 Token 发到聊天。

## 验收边界

单元测试覆盖状态机、安装顺序、签名/篡改、备份失败和链接拒绝、进度及显式安装。桌面验收必须区分本地更新源与真实 GitHub；分别记录“启动包”“安装成功”“更新后重启”“数据完整”和“真实模型服务”，一个通过不能代替其余项目。
