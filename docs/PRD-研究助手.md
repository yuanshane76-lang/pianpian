# 纸研研究助手 PRD

版本：v0.1
日期：2026-10-12
状态：首版已实现，真实三轮视觉验收完成；详见 [验收记录](./验收-研究助手-2026-10-12.md)

## 1. 背景与目标

纸研工作台当前以 PDF 阅读、段落翻译和单次问答为核心。用户下一步需要一个可以持续对话的研究助手，让“读懂当前论文”“查找相关论文”“把结果加入文献库”形成一条连续的工作流，并为后续读书笔记、研究卡片和文档生成留下稳定的扩展边界。

本版本的目标是交付一个可在桌面端验收的 Agent 闭环：

1. 用户可以在当前论文上下文中连续提问。
2. Agent 可以读取当前论文的标题、元数据和解析后的阅读块，回答时引用页码或段落。
3. Agent 可以调用文献检索工具，返回结构化的论文候选。
4. Agent 可以调用受控的“加入文献库”工具；涉及写入用户数据时先由用户确认。
5. 界面能够清楚呈现回答、工具调用、执行状态、错误和需要确认的动作。
6. 没有配置模型密钥时明确阻止 Agent 启动并引导配置，不伪造回答或检索结果。

## 2. 用户与核心场景

### 2.1 目标用户

需要阅读英文论文的中文用户，尤其是希望边读边查、边查边整理的学生和研究人员。

### 2.2 首批场景

#### 场景 A：理解当前论文

用户打开一篇已经完成解析的论文，在研究助手中提问：

> 这篇论文的研究问题、方法和主要结论是什么？

Agent 读取当前论文上下文，返回中文解释，并标注能够支撑回答的页码或阅读块。

#### 场景 B：围绕论文追问

用户继续提问：

> 作者为什么采用这个实验设计？这个结论有什么限制？

Agent 复用当前会话上下文，结合当前论文内容回答，不要求用户重复上传或复制原文。

#### 场景 C：查找相关论文

用户提问：

> 查找近五年与这个研究问题相关的论文。

Agent 调用文献检索工具，返回标题、作者、年份、DOI、来源链接和摘要片段。检索结果以候选形式出现，不能默默写入文献库。

#### 场景 D：加入文献库

用户要求：

> 把第 2 篇加入我的文献库。

Agent 调用加入工具，界面展示待写入的论文信息；用户确认后，前端复用现有文献库持久化逻辑完成写入，并把结果回传给 Agent。

## 3. 产品范围

### 3.1 本版本包含

- 研究助手入口和多轮消息列表。
- 当前论文上下文注入。
- Agent 流式回答。
- 工具调用状态卡片：
  - 读取当前论文；
  - 搜索本地文献库；
  - 搜索公开学术元数据；
  - 请求加入文献库；
  - 生成和保存 Markdown 阅读笔记草稿。
- 工具执行成功、失败、等待用户确认三种状态。
- 加入文献库前的确认交互。
- 论文检索结果的结构化卡片。
- 当前论文阅读块的页码引用跳转入口；检索候选展示 DOI 和来源元数据。
- 未配置服务时的配置引导和错误反馈。
- 当前打开页面内的会话消息保留；退出页面或重启后不会恢复历史。
- 文献库中的独立研究入口；不导入 PDF 也可从主题开始检索。

### 3.2 本版本不包含

- 自动下载全文 PDF。
- 自动绕过付费墙或登录限制。
- 自动生成最终学位论文或投稿文稿。
- 多 Agent 编排。
- 后台定时检索。
- 跨设备同步。
- 将用户 API 密钥写入 Pi 默认的明文认证文件。

## 4. 功能需求

### FR-01 多轮对话

- 输入框支持普通发送和 `Ctrl/⌘ + Enter` 发送。
- 发送后显示用户消息、Agent 思考/执行状态和回答。
- Agent 生成期间支持停止。
- 网络或模型失败时保留用户问题，并提供重试。
- 新问题可以复用同一会话上下文。

### FR-02 当前论文理解

- Agent 启动或切换论文时获得当前论文的稳定 ID、标题、作者、年份和带页码的阅读块。
- 阅读块沿用现有稳定 block ID、页码与文本；坐标由已有 PDF 阅读层消费，不把位置作为引用身份。
- Agent 回答中的引用显示页码或段落标识。
- 当前论文未完成 MinerU 解析时，明确提示暂不可进行全文理解。

### FR-03 文献检索

- 检索工具输入包含查询词和可选数量上限；年份要求由模型在候选中筛选，首版不提供结构化年份过滤。
- 首版使用 Crossref 公开学术元数据接口；检索适配器与 Agent 工具分离。覆盖范围取决于该来源，不能宣称已穷尽全网。
- 每条结果包含标题和可用作者、年份、DOI、落地页；摘要仅在来源提供时展示，缺失字段不补造。
- 检索失败时以工具错误卡片展示原因，不伪造结果。
- 检索结果不能直接覆盖本地论文记录。

### FR-04 文献库工具

- Agent 可以搜索当前本地文献库。
- Agent 可以请求加入文献库。
- 写入动作必须展示论文元数据和“确认加入”操作。
- 用户拒绝后，Agent 收到明确的拒绝结果。
- 加入动作复用现有 `src/services/library.ts` 的存储逻辑。
- 不能因为 Agent 重试而重复创建同一 DOI 或同一稳定来源论文。

### FR-05 工具链呈现

- 工具卡片显示中文名称、执行状态和关键参数摘要。
- 支持 `等待执行`、`执行中`、`已完成`、`失败`、`等待确认`。
- 工具输出过长时默认折叠，用户可以展开查看结构化结果。
- 工具调用和回答在同一条消息时间线上显示。

### FR-06 设置与安全

- Agent 使用现有服务配置中的模型服务和密钥。
- API 密钥继续由 Electron 主进程的系统安全存储管理。
- 渲染进程只能通过受限 IPC 调用 Agent，不能取得密钥。
- 默认关闭 Pi 内置工具，只注册纸研显式允许的工具。
- 工具参数经过 schema 校验，拒绝越权路径、任意命令和任意文件读写。

### FR-07 未配置服务

- 当前模型没有密钥时，研究 Agent 不创建会话、不调用外部服务。
- 输入区显示配置入口，启动失败显示中文错误和重试路径。
- 页面可以继续阅读本地 PDF；模型失败不影响 PDF 阅读。

### FR-08 文档草稿

- Agent 可以组织中文 Markdown 并调用文档工具生成草稿。
- 草稿卡片提供原生保存对话框，由用户选择保存位置。
- 首版导出 Markdown，后续再接 Word、富文本和独立读书笔记数据。

## 5. 非功能需求

### NFR-01 可理解性

界面文案优先使用中文。Agent 的工具名称、状态和错误均使用用户可理解的描述。

### NFR-02 稳定性

- 单个工具失败不应导致整个阅读器崩溃。
- Agent 失败不影响已经就绪的 PDF 阅读。
- 切换论文时取消上一论文的未完成请求，避免消息串台。

### NFR-03 性能

- 打开研究助手不应阻塞 PDF 首屏。
- 工具状态优先于最终回答显示。
- 大量阅读块进入 Agent 前进行长度限制和摘要化，避免一次请求超过上下文窗口。

### NFR-04 可测试性

- Agent 事件协议可独立测试。
- 工具执行器支持依赖注入，文献检索可使用合成响应测试。
- 工具执行器和 Pi session adapter 支持依赖注入；自动化测试使用假的 Pi session 或本地模拟 SSE 模型，产品运行时不包含演示逻辑。

## 6. 验收标准

### AC-01 多轮问答

使用真实 MinerU 解析测试论文后打开原始 PDF，通过真实模型完成 2–3 轮对话。每轮有完整用户输入与 Agent 回答，后续轮次能使用前轮上下文。最终验收必须在 Electron 前端进行，模型或检索响应不得替换为模拟结果。

### AC-02 工具链

发送“查找相关论文并告诉我最值得先读哪一篇”。界面应依次或并行显示读取当前论文、检索文献和最终回答，工具卡片能展示完成状态。

### AC-03 受控写入

发送“把检索结果第 1 篇加入文献库”。界面应出现待确认卡片；确认后文献库出现该记录；拒绝后记录不出现且会话收到拒绝结果。

### AC-04 失败可见

让检索适配器返回错误。界面应显示中文失败卡片，并保留用户问题和重试入口。

### AC-05 安全边界

测试代码和 UI 无法读取密钥；IPC 只开放定义好的 Agent 通道；Agent 工具不能执行任意系统命令或访问任意文件路径。

### AC-06 视觉验收

研究助手与现有浅色学术风格一致，消息、工具卡片、引用和确认动作有明确层级；窄窗口下不出现横向溢出，工具执行期间输入区仍可操作停止。

保留真实执行中、流式回答中和结束后的截图及脱敏事件统计，核对实际工具输入输出与前端结果。验收链路为“读取解析原文及检索文献 → 确认加入文献库 → 生成并保存阅读笔记”，共三轮完整对话。单元测试和模拟服务桌面测试只能作为回归证据，不能代替最终真实服务视觉验收。

### AC-07 文档保存

生成阅读笔记后应出现草稿卡片，通过 Electron 保存边界导出可读取的 UTF-8 Markdown；取消保存不报成功。
