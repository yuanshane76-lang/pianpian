# 纸研研究助手技术选型

日期：2026-10-12
对应 PRD：[PRD-研究助手.md](./PRD-研究助手.md)

## 1. 结论

首版采用“Pi SDK 运行时 + 纸研受控工具 + Electron 主进程桥接 + React 工具时间线”的组合。

- Pi 负责 Agent 会话、模型消息、流式事件和工具调用循环。
- Electron 主进程负责密钥、模型配置、外部学术检索和工具权限。
- React 渲染进程负责中文交互、工具状态卡片、确认动作和文献库状态。
- 纸研自己的工具协议包在 Pi 之上，避免把产品数据模型绑定到某个桌面壳项目。

参考实现选择 [TryLoveMe/picode](https://github.com/TryLoveMe/picode)。它与纸研的 Electron + React 技术栈接近，使用 Pi 的 RPC/事件模型呈现流式 Markdown、思考和工具卡片，适合作为交互与桥接设计参考。实现时保留纸研现有的安全 IPC、文献库和 PDF 数据边界，不直接复制其文件管理和通用编码 Agent 能力。

## 2. 候选比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 直接接 `@earendil-works/pi-coding-agent` SDK | 事件和工具类型完整，能在主进程内限制工具；不需要额外 Node 子进程 | 需要适配当前 Pi API；模型提供商配置要自建 | 首版采用 |
| 参考 Picode 的 Pi RPC 子进程模式 | 与成熟桌面壳接近，隔离性好，后续接 Skills/MCP 方便 | 自定义纸研工具要跨进程传递；Pi 的认证和会话文件需要额外安全处理 | 作为后续隔离方案和交互参考 |
| 直接嵌入另一个 Pi 桌面项目 | UI 和命令能力现成 | 产品边界、数据模型、许可证和安全模型不匹配；Tauri 项目还会引入运行时迁移 | 不采用 |
| 自建 Agent 循环 | 完全可控 | 要重复实现工具循环、取消、流式、错误恢复和会话 | 不采用 |

## 3. 运行时架构

```text
React ResearchAssistant
        │ 受限 IPC：start / prompt / abort / approve
        ▼
Electron preload allowlist
        ▼
Electron main：ResearchAgentRuntime
        ├─ Pi AgentSession
        ├─ Paper context adapter
        ├─ Crossref metadata search adapter
        ├─ Library action approval bridge
        └─ safeStorage-backed service settings
```

### 3.1 为什么首版在主进程调用 Pi

纸研已有的模型配置和密钥访问都在 Electron 主进程。把 Pi SDK 放在主进程可以让 API 密钥留在安全边界内，也能让自定义工具直接复用 Electron 的网络和持久化适配器。Pi 内置工具首版全部关闭，只传入纸研自定义工具。

后续如果需要加载第三方 Skill、MCP 或更复杂的社区扩展，再把 Agent runtime 移到受控的 Pi RPC 子进程，并沿用当前事件协议。这样 UI 和产品工具不会被运行位置绑死。

## 4. Pi 接入方式

依赖：

```text
@earendil-works/pi-coding-agent@1.1.0
```

接入约束：

1. 使用 `createAgentSession` 创建会话。
2. 使用 `ModelRuntime.create()` 和 `InMemoryCredentialStore`，通过 `setRuntimeApiKey()` 设置凭据，不写入 Pi 默认认证文件。
3. 使用 `ModelRuntime.registerProvider()` 注册纸研当前服务配置对应的 OpenAI-compatible 模型；关闭模型目录网络刷新。
4. 使用 `noTools: "all"`，只传入纸研自定义工具。
5. 监听消息增量和结束事件，工具包装器发布工具开始、结束、审批和错误；统一转换为纸研 `ResearchAgentEvent`，不展示模型私有思考。
6. 每次启动会话时传入当前论文上下文和本地文献库的轻量元数据。

## 5. 工具边界

### `read_current_paper`

只读取由渲染进程明确传入的当前论文上下文。返回标题、元数据、页级或段落级阅读块。工具不接受文件路径，不直接访问用户目录。

### `search_library`

只搜索当前会话传入的本地文献库元数据。首版不让 Agent 直接扫描 localStorage 或数据库。

### `search_literature`

通过 Crossref REST API 检索公开元数据，不自动下载全文，也不宣称覆盖全部互联网论文。使用 `fetch` 依赖注入、超时和数量上限；单元测试使用合成响应。

### `add_paper_to_library`

它是一个需要用户确认的写工具：

1. Agent 提交论文元数据。
2. 主进程发出 `approval_required` 事件。
3. React 展示确认卡片。
4. 用户确认后，渲染进程复用现有文献库服务写入，并把批准结果回传主进程。
5. Agent 收到工具结果，继续回答。

工具不能接收本地路径、任意代码或未声明的额外字段。

确认采用两步协议：主进程先保留有效审批，前端收到成功后再次核对会话与审批身份，再同步持久化并提交结果。停止、切换论文、卸载面板和会话结束立即使前端审批失效，晚到的保留结果不能触发写入。入库工具在发出审批前规范 DOI 链接并拒绝非法 URL。

### `create_document`

由模型组织 Markdown，工具返回结构化草稿。界面发起 `save-document` IPC 后，由主进程校验长度、打开原生保存对话框并写入 UTF-8 文件。Agent 不接收或决定本机路径。

## 6. 数据与会话

首版采用两层状态：

- Agent 运行时状态：Electron 主进程内的 Pi 会话，只在当前应用运行期间存在。
- 产品消息状态：React 在当前页面内保存消息；切换助手页签保留，退出页面或重启清空，尚未实现持久化历史。

论文引用使用现有稳定 `PaperRecord.id` 和阅读块 ID。缓存或恢复不能使用 DOM 序号、消息数组下标或页面位置。

## 7. 失败与恢复

- 模型未配置：阻止 Agent 启动并提示用户配置服务。
- 模型请求失败：发送 `agent_error`，保留已显示的工具卡片和用户问题。
- 工具失败：只结束当前工具，Agent 可以基于错误决定是否重试。
- 切换论文：主进程 abort 当前会话，前端清理未完成状态。
- 用户拒绝写入：返回结构化 `rejected` 工具结果，Agent 继续对话。
- 本地检索输出按序列化字符预算限制，返回 `totalMatches` 和 `truncated`，用户可缩小关键词继续查询。
- 事件协议不合法：显示工具失败与中文错误，终止本轮，避免丢失审批后一直等待。

## 8. 安全要求

- renderer 不接触模型密钥。
- preload 只暴露固定 IPC 通道。
- 主进程校验 sender、参数 schema、文本长度和数组上限。
- 工具不开放 shell、任意文件、任意 URL 请求或任意路径。
- 外部搜索只允许配置好的公开学术 API 域名。
- 测试和 CI 使用合成论文与假密钥。

## 9. 验证策略

1. 协议单元测试：事件归一化、工具状态、审批结果和参数限制。
2. 工具单元测试：本地文献检索、公开检索适配器、去重规则。
3. React 测试：消息时间线、工具卡片、确认/拒绝、失败重试。
4. Electron 集成测试：IPC allowlist 和 Pi Agent 工具链；测试通过注入假的 Pi session 或本地模拟 SSE 模型，不把演示逻辑编进产品运行时。
5. `npm run check`：项目规定的测试、类型检查和构建。
6. Windows 桌面验收：真实 Electron 窗口、多轮对话、确认/拒绝/停止、Markdown 保存、原始 PDF 引用跳转和窄窗口布局。
7. Pi SDK 冒烟：本地模拟 SSE 模型驱动真实 Pi 工具循环，检查注册工具仅限五个产品工具。
8. Windows ZIP 打包及解压后的启动验证。

## 10. 主要取舍

本版本优先把工具协议和桌面交互做成可验证的闭环，外部论文搜索只返回元数据。全文获取、复杂 Skill/MCP 装载和持久化会话都留到后续版本，避免破坏纸研当前“原始 PDF 是唯一阅读面”的产品边界。
