# 学术论文阅读器 — 产品需求文档 (PRD)

> 版本：v3.0 | 日期：2026-05-10 | 个人本地使用 | 全文上下文 + MinerU + SQLite

---

## 一、产品概述

### 1.1 产品定位

一款**本地运行的学术论文阅读器**，上传 PDF 后通过 MinerU API 高精度解析全文（完美处理公式、表格、排版），利用 DeepSeek 128K 长上下文将**整篇论文完整送入 AI**，元信息、缓存、对话历史均存入本地 SQLite。个人使用，不部署。

### 1.2 核心价值

> **不截断、不妥协——整篇论文喂给 AI。** 上传一篇论文，全文进入上下文窗口，AI 通读整篇后帮你提炼核心信息、翻译任意段落、解释陌生术语，问答时能引用论文任意位置。把你的阅读负担降到零。

### 1.3 用户画像（你自己）

| 属性 | 描述 |
|------|------|
| 英文水平 | 能读但吃力，专业术语需要辅助 |
| 技术背景 | AI/ML 方向，用过 LangChain/Agent 框架 |
| 核心场景 | 面试准备、竞品调研、学术跟踪 |
| 已有资源 | MinerU API Token + DeepSeek API Key（128K 上下文） |

## 二、用户故事

### US-1：上传论文，AI 通读全文后生成元信息

- **场景**：拿到一篇新论文 PDF，想快速了解它在讲什么
- **操作**：拖拽 / 选择 PDF 文件上传
- **期望结果**：
  - PDF 通过 MinerU API 高精度解析（公式/表格/排版均保留）
  - 论文标题、作者、发表会议/年份
  - 一句话总结（本文做了什么）
  - 核心贡献（3-5 条）
  - 关键创新点（1-2 个）
  - 一页纸逻辑链（问题→方法→验证→局限）
  - **全文送入 DeepSeek**，AI 通读整篇论文生成元信息，不做截断

### US-2：沉浸式阅读原文 + 智能翻译

- **场景**：读论文原文时，某一段落看不懂
- **操作**：点击任意段落
- **期望结果**：
  - 弹出中文翻译（保留技术术语原文）
  - 段落结构解析（这一段在论文中的作用：承上启下？核心论证？实验结论？）
  - **翻译时 AI 已通读全文**，能根据上下文准确翻译术语，不会断章取义

### US-3：术语一键查询（全文感知）

- **场景**：看到陌生术语（如 "self-consistency decoding"）
- **操作**：选中术语文本，点击"解释"
- **期望结果**：用通俗语言解释该术语，结合论文全文中该术语的每个出现位置交叉解释

### US-4：自由问答（全文引用）

- **场景**：读完某个部分有疑问
- **操作**：在问答框输入问题
- **期望结果**：AI 结合论文全文回答，精准引用原文位置（如 "见 Section 3.2 第 3 段"）

| **AI 论文元信息生成** | P0 | 全文送入 DeepSeek，通读整篇后生成标题/作者/贡献/创新点/逻辑链 |

### 3.2 功能详细说明

#### F1：PDF 上传与 MinerU 全文解析

本版必须使用 MinerU API 解析 PDF，以完美处理论文中的数学公式、表格、多栏排版。MinerU 要求文件 URL（公网可访问），本地文件的处理流程如下：

**上传解析流程（4 步）：**

```
用户拖拽 PDF
    │
    ▼
① 后端接收文件，保存到 loop/papers/{paper_id}.pdf
    │
    ▼
② 上传到临时文件托管服务，获取公网 URL
   方案 A（主）：file.io — POST multipart，免费 1 次下载后自动销毁
   方案 B（备）：gofile.io — 免费、无下载次数限制、存储 30 天
   方案 C（备）：0x0.st — 极简 curl/POST，返回纯文本 URL
    │
    ▼
③ 调用 MinerU API，传入公网 URL，轮询解析结果
   → 下载 ZIP（含 Markdown + JSON）
    │
    ▼
④ 解析 MinerU 输出，提取结构化全文 → 存入 SQLite
```

- **方式**：拖拽到页面 / 点击上传按钮
- **上传限制**：单文件 ≤ 50MB，≤ 200 页
- **解析质量**：MinerU vlm 模型，公式渲染为 LaTeX，表格保留结构，章节自动识别
- **临时 URL**：使用 file.io API（上传后自动过期，无需手动清理）
- **容错**：若临时 URL 服务不可用，自动降级到备选方案
- **结果缓存**：MinerU 解析结果（MD + JSON）存入 SQLite，同一篇论文不重复解析

**MinerU 输出结构**（存入 SQLite）：
```
paper_meta: 标题、作者、摘要、关键词（MinerU 自动提取）
paper_sections: [{section_id, heading, level, content, page_num}]
paper_paragraphs: [{para_id, section_id, text, page_num, type}]
paper_tables: [{table_id, page_num, caption, html_content}]
paper_formulas: [{formula_id, page_num, latex, context_text}]
```

#### F2：AI 元信息生成（全文感知）

上传完成后，将**论文完整全文**送入 DeepSeek，生成论文卡片：

```
📄 论文标题
👥 作者 | 📅 发表会议/年份 | arXiv ID
━━━━━━━━━━━━━━━━━━━━━━━━━━━
💡 一句话总结
   [本文做了什么，为什么重要]

🎖️ 核心贡献
   1. ...
   2. ...
   3. ...

✨ 关键创新点
   - 创新1：...
   - 创新2：...

🔗 逻辑链
   🎯 问题 → ❌ 前人不足 → ✅ 本文方法 → 📊 验证 → ⚠️ 局限
```

- **实现**：将论文完整全文发送给 DeepSeek，要求结构化 JSON 输出
- **缓存**：生成后存入 SQLite，下次打开同一篇论文直接展示，不重复调用 AI

```
│  we explore...       │  │ 这一段是...        │  │
│                      │  ├──────────────────┤  │
│  [段落3] ← 可点击    │  │ 🔑 关键术语        │  │

│                      │  └──────────────────┘  │
```

- **原文面板**：按段落分割，每段可点击高亮
- **AI 面板**：展示选中段落的翻译 + 作用说明 + 术语
- **术语选中**：在原文面板中选中文本 → 弹出"解释该术语"按钮

#### F4：段落翻译与讲解（全文上下文）

点击任意段落后，AI 面板展示（AI 已通读全文，翻译准确且上下文连贯）：

```
🇬🇧 原文
[段落英文原文]

🇨🇳 翻译
[中文翻译，技术术语保留英文标注，基于全文上下文准确翻译]

🧠 这一段在论文中的作用
[承上启下 / 核心论证 / 实验描述 / 总结观点]

🔑 关键术语
- embedding（嵌入向量）：将文本转化为数字向量
- hallucination（幻觉）：模型生成看似正确但错误的内容
```

#### F5：术语解释（全文交叉引用）

在原文面板选中文本后，AI 结合论文全文交叉解释该术语：

```
选中的文本：self-consistency decoding

🔍 术语解释
自一致性解码（Self-Consistency Decoding）是一种推理增强技术：
对同一问题采样多条推理链，取出现最多的答案作为最终结果。
就像让5个人独立解题，然后投票选最被认可的答案。

📎 在这篇论文中的用法
本文用 CoT-SC（CoT + Self-Consistency）作为 baseline，
ReAct 只用 3-5 个 SC 样本就达到了 CoT-SC 用 21 个样本的效果。
该术语还出现在 Section 3.1、Section 5.2（消融实验）。
```

#### F6：自由问答（全文引用）

底部固定问答框，AI 通读全文后精准回答：

```
💬 问一个关于这篇论文的问题...
[输入框__________________________________] [发送]

示例：ReAct 和 CoT 到底有什么区别？
示例：这篇论文的实验用了什么数据集？
示例：这个方法有什么局限性？
```

- AI **通读全文**后回答，不被截断限制
- 精准引用论文原文对应位置（如 "参见 Section 3.2 第 2 段"）
- 用通俗语言解释，保留技术术语原文

### 4.3 API 集成细节

#### DeepSeek V4 Flash（全文上下文策略）

```
Endpoint: POST https://api.deepseek.com/chat/completions
Auth:     Authorization: Bearer <DEEPSEEK_API_KEY>
Model:    deepseek-v4-flash
Context:  128K tokens — 足够容纳任何学术论文全文（典型论文 ~20K tokens）

核心策略：全文上下文窗口
- 上传论文后，将 full_text 完整保存在后端内存/缓存中
- 每次 AI 调用（翻译/解释/问答）都携带全文作为 context
- 利用 DeepSeek 长上下文优势，让 AI 对整篇论文有全局理解
- 不会出现"只看摘要"或"只看前8000字"的信息丢失问题

调用模式：
┌─────────────────────────────────────────────┐
│  元信息生成                                  │
│  System: 论文分析专家                        │
│  User:   全文 + "请生成结构化分析JSON"        │
│  Tokens: ~20K (论文) + ~500 (prompt) ≈ 20K   │
├─────────────────────────────────────────────┤
│  段落翻译                                    │
│  System: 翻译专家                            │
│  User:   全文 + "请翻译第{N}段：[段落文本]"   │
│  Tokens: ~20K (论文) + ~300 (段落+prompt)    │
├─────────────────────────────────────────────┤
│  术语解释                                    │
│  System: 术语解释专家                         │
│  User:   全文 + "请解释术语'XXX'在本文中的含义"│
│  Tokens: ~20K + ~200 ≈ 20K                   │
├─────────────────────────────────────────────┤
│  自由问答                                    │
│  System: 论文助教                             │
│  User:   全文 + 用户问题                      │
│  Tokens: ~20K + ~200 ≈ 20K                  │
└─────────────────────────────────────────────┘

System Prompt:
"你是一位AI领域的论文精读助教。你的用户英文非母语，
需要你帮助理解英文学术论文。翻译时保留技术术语原文并标注中文，
用通俗语言解释复杂概念，并用生活化比喻帮助理解。
你会收到论文全文，请基于全文理解回答问题，不要遗漏细节。"

每次调用根据任务类型（翻译/解释/总结/问答）构造不同的 System Prompt
元信息生成使用 JSON Output 格式，确保结构化返回
```

#### MinerU API（必选 P0 — PDF 解析主引擎）

MinerU 是 PDF 解析主引擎，必须在上传后调用。核心挑战：MinerU API 要求文件 URL（公网可访问），本地文件需先获取临时公网 URL。

**完整工作流：**

```
Step 1: 上传 PDF 到临时托管 → 获取公网 URL
─────────────────────────────────────────────
方案 A — file.io（主）:
  POST https://file.io
  Body: multipart/form-data { file: @paper.pdf }
  Response: { "success": true, "link": "https://file.io/xxxxx" }
  特点: 免费、1次下载后自动销毁、无需清理

方案 B — gofile.io（备）:
  POST https://store1.gofile.io/uploadFile
  Body: multipart/form-data { file: @paper.pdf }
  Response: { "status": "ok", "data": { "downloadPage": "https://gofile.io/d/xxxxx" } }
  特点: 免费、无下载次数限制、存储30天

方案 C — 0x0.st（备）:
  POST https://0x0.st
  Body: multipart/form-data { file: @paper.pdf }
  Response: "https://0x0.st/xxxx.pdf"  (纯文本 URL)
  特点: 极简、512MB限制、无过期时间（但可删除）

Step 2: 调用 MinerU 创建解析任务
─────────────────────────────────────────────
  POST https://mineru.net/api/v4/extract/task
  Headers: Authorization: Bearer <MINERU_TOKEN>
  Body: {
    "url": "<Step1获得的公网URL>",
    "model_version": "vlm"
  }
  Response: { "task_id": "xxx" }

Step 3: 轮询 MinerU 任务状态
─────────────────────────────────────────────
  GET https://mineru.net/api/v4/extract/task/{task_id}
  Headers: Authorization: Bearer <MINERU_TOKEN>
  
  状态: pending → processing → completed
  Response (completed): {
    "status": "completed",
    "result": { "zip_url": "https://...download.zip" }
  }

Step 4: 下载并解析 MinerU 结果
─────────────────────────────────────────────
  GET {zip_url} → 下载 ZIP
  解压内容:
    ├── {paper_name}.md       # Markdown 格式全文（含公式 LaTeX、表格 HTML）
    └── {paper_name}/         # 结构化 JSON
        ├── content_list.json # 页面内容列表
        ├── model.json        # 模型识别结果（段落/公式/表格/图片位置）
        └── ...
  
  解析后结构化存入 SQLite（按 section/paragraph/table/formula 分类）
```

**file.io Python 实现参考：**
```python
import httpx

async def upload_to_fileio(file_path: str) -> str:
    async with httpx.AsyncClient() as client:
        with open(file_path, "rb") as f:
            resp = await client.post(
                "https://file.io",
                files={"file": f}
            )
        data = resp.json()
        if data.get("success"):
            return data["link"]
        raise Exception(f"file.io upload failed: {data}")
```

#### MinerU MCP 集成（备选方案）

MinerU 官方和社区提供了 MCP Server 封装，可通过 MCP 协议调用 MinerU 解析能力。这对本项目的意义分析如下：

**MinerU MCP 可用方案：**

```
方案 1 — 官方远程 MCP（Streamable HTTP）:
  无需本地安装，直接连接 MinerU 云端 MCP 服务
  Config: { "url": "https://mcp.mineru.net/mcp", "type": "streamableHttp" }
  
方案 2 — 本地安装 MCP Server（CLI）:
  pip install mineru-mcp
  或: uvx mineru-open-mcp
  Config: { "command": "uvx", "args": ["mineru-open-mcp"] }
```

**MCP 提供的核心工具：**

| 工具 | 功能 | 对项目的意义 |
|------|------|-------------|
| `parse_documents` | 统一接口，接受 URL 或本地路径，自动轮询+MinerU解析+读取结果 | 高度契合 |
| `create_batch_parsing_task` | 批量上传本地文件 | 契合 |
| `get_ocr_languages` | 获取 OCR 语言列表 | 辅助 |

**集成分析：**

| 维度 | REST API + file.io（当前方案） | MCP Server |
|------|-------------------------------|------------|
| 架构匹配度 | ✅ Web App 原生 HTTP 调用 | ⚠️ MCP 为 AI Agent 设计，非 Web App |
| 复杂论文解析 | ✅ 直接调用，完整控制 | ✅ 同样能力 |
| 临时 URL 依赖 | ❌ 需要 file.io/gofile | ❌ **底层仍调用同一 API，仍需公网 URL** |
| 后端复杂度 | ✅ 3 个 httpx 调用 | ⚠️ 需引入 `fastmcp` 客户端、管理 MCP 连接生命周期 |
| 代码量 | ~30 行 Python | ~20 行 Python（但多了 MCP 依赖） |

**结论：**

> MCP 方案在本质上与直接 REST API 方案等价——MinerU MCP Server 底层调用的仍然是同一套 MinerU REST API（`/api/v4/extract/task`），**不可绕过临时公网 URL 的需求**。
>
> MCP 的价值在于为 AI Agent（如 Claude Desktop、VS Code Copilot）提供了标准化的工具调用接口，但对于本项目这种 FastAPI Web App，直接使用 REST API 更简洁、更可控。
>
> **本项目采用 REST API 直连方案（§4.3.2），MCP 方案作为备选记录于此，不阻塞开发。**

### 4.5 本地 SQLite 存储设计

数据库文件：`loop/paper_reader.db`

**SQLite Schema：**

```sql
-- 论文主表
CREATE TABLE papers (
    id          TEXT PRIMARY KEY,        -- paper_id (如 react_2022)
    filename    TEXT NOT NULL,           -- 原始文件名
    file_path   TEXT NOT NULL,           -- 本地 PDF 路径
    file_size   INTEGER,                -- 文件大小 (bytes)
    status      TEXT DEFAULT 'pending',  -- pending/parsing/parsed/error
    created_at  TEXT DEFAULT (datetime('now')),
    updated_at  TEXT DEFAULT (datetime('now'))
);

-- 论文元信息 (MinerU 自动提取)
CREATE TABLE paper_meta (
    paper_id    TEXT PRIMARY KEY REFERENCES papers(id),
    title       TEXT,
    authors     TEXT,
    abstract    TEXT,
    keywords    TEXT,                    -- JSON array
    venue       TEXT,
    year        TEXT,
    arxiv_id    TEXT
);

-- AI 生成的元信息 (DeepSeek 输出)
CREATE TABLE ai_meta (
    paper_id        TEXT PRIMARY KEY REFERENCES papers(id),
    one_sentence    TEXT,                -- 一句话总结
    contributions   TEXT,                -- JSON array
    innovations     TEXT,                -- JSON array
    logic_chain     TEXT,                -- JSON object {problem, flaws, method, evidence, limitations}
    terms           TEXT,                -- JSON array [{en, zh, explain}]
    generated_at    TEXT DEFAULT (datetime('now'))
);

-- 章节 / 段落
CREATE TABLE sections (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    paper_id    TEXT NOT NULL REFERENCES papers(id),
    section_order INTEGER,              -- 章节序号
    heading     TEXT,                    -- 章节标题 (如 "1. INTRODUCTION")
    level       INTEGER DEFAULT 1,      -- 标题层级 (1=一级, 2=二级)
    content     TEXT,                    -- 该章节完整文本
    page_start  INTEGER,
    page_end    INTEGER
);

-- 段落（细粒度）
CREATE TABLE paragraphs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    paper_id    TEXT NOT NULL REFERENCES papers(id),
    section_id  INTEGER REFERENCES sections(id),
    para_order  INTEGER,                -- 段落序号
    text        TEXT NOT NULL,          -- 段落原文
    page_num    INTEGER
);

-- 表格
CREATE TABLE tables (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    paper_id    TEXT NOT NULL REFERENCES papers(id),
    table_order INTEGER,
    caption     TEXT,
    html_content TEXT,                   -- MinerU 输出的 HTML 表格
    page_num    INTEGER
);

-- 公式
CREATE TABLE formulas (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    paper_id    TEXT NOT NULL REFERENCES papers(id),
    formula_order INTEGER,
    latex       TEXT NOT NULL,          -- LaTeX 公式
    context     TEXT,                    -- 上下文文本
    page_num    INTEGER
);

-- 对话历史
CREATE TABLE chat_history (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    paper_id    TEXT NOT NULL REFERENCES papers(id),
    role        TEXT NOT NULL,          -- 'user' | 'assistant'
    content     TEXT NOT NULL,
    created_at  TEXT DEFAULT (datetime('now'))
);

-- 索引
CREATE INDEX idx_sections_paper ON sections(paper_id);
CREATE INDEX idx_paragraphs_paper ON paragraphs(paper_id);
CREATE INDEX idx_chat_paper ON chat_history(paper_id);
```

## 八、验收场景

```
操作：拖拽 ReAct.pdf 到上传区
预期：
1. 显示分步进度（file.io 上传 → MinerU 解析 → DeepSeek 元信息）

```

```
1. 段落高亮 + 左侧蓝条
2. AI 面板显示：🇬🇧原文 + 🇨🇳翻译 + 🧠段落作用 + 🔑术语

```
