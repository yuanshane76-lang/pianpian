# 纸研工作台：自动解析与增量翻译交互方案

日期：2026-10-08  
状态：已实现首版，持续验证

## 一、目标

用户导入英文论文后，不再需要先进入阅读器再手动点击 MinerU。产品自动启动解析，同时尽快给出一部分中文内容，让用户在等待结构化解析时已经可以开始阅读。

目标流程：

```text
选择 PDF
  -> 本地保存原文
  -> 立即进入阅读器
  -> 本地提取临时段落
  -> 自动启动 MinerU
  -> 翻译首屏和前几段
  -> MinerU 完成后把结构识别结果叠加到同一 PDF 阅读面
  -> 继续按视口和用户操作增量翻译
```

## 二、必须遵守的技术事实

当前 MinerU v4 托管接口在任务完成前只返回任务状态和页级进度，不返回可以直接展示的中间段落。结构化内容和图表资源要等 `full_zip_url` 可用后整体下载。

因此“解析过程中同步翻译”采用两层内容源：

1. **本地临时层**：使用 PDF.js 快速提取文本，生成临时段落，负责让用户尽快开始阅读和翻译；
2. **MinerU 正式层**：MinerU 完成后生成章节、段落、图表、表格和公式，替换临时层，作为最终阅读内容。

两层之间不使用 DOM 顺序或临时块 ID 关联，而使用规范化正文内容签名关联。PDF 画布始终不替换，MinerU 完成后只升级交互块和语义信息；这样已经生成的译文不会因为 MinerU 重新分块而丢失。

## 三、导入后的用户流程

### 1. 选择文件后立即建立文献

文件选择成功后立即：

- 保存原始 PDF；
- 创建文献库记录；
- 进入阅读器；
- 默认展示原始 PDF；
- 后台启动本地正文提取；
- 如果 MinerU 已配置且自动解析已启用，自动启动 MinerU。

不再显示一个阻塞式“导入成功”页面。

### 2. 首次自动上传确认

第一次使用自动 MinerU 时显示一次确认：

> 导入后自动使用 MinerU 整理论文  
> 这会把完整 PDF 上传到 MinerU，用于提取自然段、图表、表格和公式，可能消耗解析额度。原始文件仍保存在本机。

提供两个操作：

- `这次开始解析`：只对当前论文生效；
- `以后导入后自动解析`：保存本地偏好，后续不再阻塞。

用户选择不自动上传时，仍然进入本地阅读，阅读器提供“开始 MinerU 解析”按钮。

### 3. 原文和交互层并行生成

进入阅读器后，不等待 MinerU：

- 原始 PDF 可以立即翻页、缩放和查看图表；
- 本地正文提取完成后，在 PDF 上叠加可点击的临时段落块；
- 临时交互层顶部显示“正在生成 MinerU 结构”；
- 段落可正常选择、复制和翻译；
- 图表、表格和公式仍直接使用 PDF 原件显示。

MinerU 完成后，临时交互块升级为正式结构化交互层，不替换 PDF 画布。

## 四、阅读器 UI 设计

### 1. 顶部流水线状态条

阅读器顶部增加固定但轻量的流水线状态条，分成三段：

```text
原文已保存 ✓   MinerU 结构解析 · 处理中   中文预览 · 已完成 3 段
```

每一段显示：

- 当前状态；
- 实际阶段文案；
- 可执行操作；
- 失败时的重试入口。

MinerU 阶段使用真实状态，不显示虚构百分比：

- 正在读取文件；
- 正在上传 PDF；
- 等待 MinerU 开始；
- MinerU 正在解析；
- 正在生成结构化内容；
- 正在下载解析结果；
- MinerU 交互层已叠加。

如果接口提供页级进度，显示“已处理 6 / 15 页”；没有有效进度时只显示阶段文案。

### 2. 右侧助手增加“处理进度”区域

右侧研究助手顶部增加一个可收起的“本次导入”区域，内容包括：

- MinerU 当前阶段；
- 中文预览翻译进度；
- 当前正在处理的段落；
- `暂停翻译`、`继续翻译`、`重试`按钮；
- 当前服务和模型；
- 已产生的提示或错误。

解析完成后该区域折叠成一行：

```text
本篇论文已完成结构化解析 · 已翻译 5 段
```

不把进度做成大面积遮罩，用户始终可以阅读和返回文献库。

### 3. 中间阅读区的临时状态

本地正文尚未完成时，中间区显示稳定尺寸的段落骨架：

- 已有文本的段落正常显示；
- 未完成的位置显示 2 到 4 个骨架段落；
- 不因为译文到达而改变段落外框尺寸；
- 首段译文到达后，在原段落下方插入紧凑的中文译文区域。

段落左侧增加轻量来源标识：

- `临时解析`：来自 PDF.js；
- `结构化解析`：来自 MinerU。

该标识只在处理期间显示，解析完成后不再打扰阅读。

### 4. 翻译展示

翻译结果有两个位置：

1. 右侧助手：展示当前选中段落或句子的完整译文；
2. 正文段落下方：展示已经自动生成的预览译文。

自动译文使用低强调样式，不抢正文焦点；用户点击段落后，右侧显示完整操作和“重新翻译”。

自动生成的译文应明确标记：

```text
自动预览译文
```

手动点击生成的译文标记：

```text
当前段落译文
```

## 五、自动翻译策略

### 1. 第一批翻译什么

不自动翻译整篇论文，避免导入一篇长论文就产生大量费用和等待时间。

第一批优先级：

1. 论文标题下方的摘要或摘要附近段落；
2. 前言/引言中的前 2 到 4 个自然段；
3. 如果无法识别摘要和章节，则翻译正文最前面的 3 个有效段落。

首批默认最多 5 个段落，且跳过标题、作者、页眉、参考文献和过短文本。

### 2. 翻译并发

默认并发数为 1，避免触发服务限流并控制费用。后续可以根据服务商和用户设置提高到 2。

队列行为：

- 同一内容签名只请求一次；
- 已有缓存的段落直接显示；
- 用户当前选中的段落拥有最高优先级；
- 当前视口内的段落优先于视口外；
- 首批预览完成后，滚动到新视口才继续排队；
- 用户手动暂停后不再产生新的模型请求，已开始的请求允许自然完成。

优先级顺序：

```text
用户当前选择 > 当前视口 > 首批预览 > 后台预取
```

### 3. 没有 AI 密钥时

MinerU 和模型服务独立：

- MinerU 已配置但模型未配置：正常自动结构解析；翻译区显示“配置翻译服务”；
- 模型已配置但 MinerU 未配置：本地 PDF.js 仍可翻译临时段落；
- 两者都未配置：原文正常打开，显示配置入口，不返回伪译文。

## 六、MinerU 完成后的切换

当 MinerU 结果下载并写入本地后：

1. 保存所有图表资源；
2. 保存解析结果；
3. 校验结果属于当前批次；
4. 将正式结构化块发布到前端；
5. 使用正文内容签名迁移已有译文；
6. 保留当前阅读页和滚动锚点；
7. 清除“临时解析”标识；
8. 显示短暂提示：

> MinerU 交互层已更新，已保留已有译文。

如果某个临时段落无法与正式段落精确匹配，不强行迁移译文；该段由用户再次点击时重新翻译。

## 七、状态模型

新增一个前端流水线状态，不把所有状态继续塞进 `parseStatus`：

```ts
type PipelineStage =
  | "saving"
  | "local-extracting"
  | "mineru-consent"
  | "mineru-uploading"
  | "mineru-processing"
  | "mineru-downloading"
  | "translating-preview"
  | "ready"
  | "partial"
  | "failed";

interface PaperPipelineState {
  paperId: string;
  source: "local" | "mineru";
  stage: PipelineStage;
  mineruProgress?: number;
  mineruMessage?: string;
  translatedCount: number;
  queuedCount: number;
  failedCount: number;
  paused: boolean;
  error?: string;
}
```

持久化边界：

- MinerU 任务和下载状态继续由 Electron 主进程持久化；
- 解析结果和原始文件继续由文档存储持久化；
- 翻译结果继续由内容签名缓存持久化；
- 翻译队列本身只保存轻量计划，应用重启后根据缓存和当前首屏重新生成，不保存密钥和完整请求。

## 八、需要改造的模块

### 主进程

- `electron/document-tasks.cjs`
  - 补充上传、解析、下载阶段的稳定消息；
  - 保持断点恢复；
  - 确保同一文献不会重复创建 MinerU 任务。

- `electron/main.cjs`
  - 继续只负责 MinerU 和模型密钥访问；
  - 不把翻译队列放入主进程，避免 UI 生命周期和网络任务耦合。

### 前端领域与服务

- 新增 `src/domain/pipeline.ts`
  - 定义流水线状态、阶段文案和翻译优先级。

- 新增 `src/services/translationQueue.ts`
  - 单并发队列；
  - 按内容签名去重；
  - 支持暂停、继续、取消当前论文后台任务；
  - 只通过现有 `zhiyan:ai:run` 调用模型。

- `src/domain/analysis.ts`
  - 统一使用论文 ID + 正文内容签名作为翻译缓存身份；
  - 不使用 MinerU 临时块 ID 作为唯一缓存键。

- `src/app/App.tsx`
  - 导入成功后启动流水线；
  - 管理临时层到正式层的替换；
  - 启动首批翻译和视口预取；
  - 处理旧结果、切换论文和迟到请求。

### 阅读器 UI

- `src/features/reader/ReaderView.tsx`
  - 增加顶部流水线状态条；
  - 保留原始 PDF 和临时交互层的并行入口。

- `src/features/reader/BlockList.tsx`
  - 支持临时块和正式块；
  - 支持正文下方的增量译文；
  - 保持稳定布局，避免译文到达时跳动。

- `src/features/reader/ReaderAssistant.tsx`
  - 增加导入处理进度区；
  - 显示暂停、继续、重试和配置入口。

## 九、异常与恢复

| 情况 | 行为 |
|---|---|
| 本地提取慢 | 原始 PDF 立即可读，显示正文骨架 |
| MinerU 上传失败 | 保留本地阅读和本地翻译，提供重试 |
| MinerU 解析中 | 继续翻译临时段落，顶部显示真实阶段 |
| MinerU 下载失败 | 不重复上传，使用已保存结果地址重试下载 |
| 单段翻译失败 | 只标记该段失败，不阻塞其他段落 |
| 模型限流 | 暂停后台预翻译，用户当前手动翻译仍可重试 |
| 应用重启 | 恢复 MinerU 任务；根据当前首屏和缓存重新建立翻译队列 |
| 正式结构与临时文本不同 | 精确签名匹配；匹配不到则不迁移，不展示错误译文 |

## 十、实现顺序

### 第一阶段：自动启动与进度状态

- 导入完成后自动进入阅读器；
- 自动启动 MinerU；
- 增加一次性自动上传确认；
- 顶部显示真实阶段；
- 修复前端优先展示 `task.message`，不直接展示原始数值。

### 第二阶段：临时交互层和首批翻译

- 本地正文提取完成即在 PDF 上显示交互层；
- 增加单并发翻译队列；
- 自动翻译首批最多 5 个段落；
- 支持暂停、继续和失败重试。

### 第三阶段：正式结果无感替换

- MinerU 结果发布后替换临时块；
- 按正文签名迁移已有译文；
- 保留滚动锚点、当前页和用户选择；
- 图表、表格和公式在正式层出现后保持原始页入口。

### 第四阶段：视口预取与恢复

- 根据当前视口继续翻译；
- 切换论文时取消旧队列；
- 重启后从缓存恢复并重新安排首屏；
- 增加完整桌面端验收。

## 十一、验收标准

1. 导入 PDF 后无需再次点击 MinerU，能够看到自动解析状态。
2. 原始 PDF 在自动解析期间始终可读。
3. 本地正文先出现时，用户可以开始阅读。
4. AI 已配置时，首批 3 到 5 个段落能在后台陆续出现中文译文。
5. 用户可以在等待期间点击任意段落并优先翻译当前段落。
6. MinerU 完成后，PDF 上的交互层自动升级为结构化结果，不丢失已经生成的译文。
7. 解析失败不影响原文阅读和已有译文。
8. 应用重启后能够继续 MinerU 任务，不重复上传。
9. 页面不会因为状态和译文到达发生明显布局跳动。
10. 没有配置模型时不生成伪译文，只提供清晰配置入口。

已完成：

- 导入后进入阅读器，并自动建立本地处理流水线；
- 本地 PDF.js 正文整理与 MinerU 任务状态并行；
- 首次自动上传确认，支持记住自动解析偏好；
- 顶部流水线状态条与右侧“本次导入”状态区；
- 单并发增量翻译队列，按摘要/引言/正文首段优先；
- 翻译队列去重、暂停、继续和失败重试；
- 自动预览译文显示在正文段落下方；
- AI 流式输出可以在译文完成前逐步显示；
- MinerU 结果完成后进入正式结构化交互层，并按内容签名继续使用翻译缓存；
- 解析失败不阻塞原始 PDF 和临时交互层。

当前边界：

- MinerU 托管接口不提供任务完成前的结构化中间结果，所以解析期间展示的是本地 PDF.js 临时正文；
- 自动翻译首批最多 5 个段落，视口滚动预取和跨重启翻译队列恢复后续继续增强；
- MinerU 的自动上传仍受一次性确认控制，取消后可在阅读器手动点击开始解析。
