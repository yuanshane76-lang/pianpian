# 纸研工作台：自动解析与按需理解

更新日期：2026-10-10

## 产品边界

导入后尽快展示原始 PDF，正文和结构解析在后台准备。模型响应足够快，不再提前生成译文。导入、解析完成、应用恢复、翻页和滚动都不触发模型请求。

```text
选择 PDF
  -> 本地保存原件与文献记录
  -> 立即进入原始 PDF 阅读面
  -> PDF.js 后台整理基础正文
  -> 按用户云端授权调用 MinerU
  -> 发布可靠坐标的段落、图表和公式交互层
  -> 用户主动触发翻译或分析
```

## 原件与解析

- 原始 PDF 是唯一阅读面，保持原有排版、图表和公式。
- 临时正文用于检索和分析上下文，不按文本顺序猜测纸面位置。
- 有可靠归一化坐标的 MinerU 结果才生成点击框。
- 原件可读性、MinerU 任务与模型分析分开维护状态；解析或模型失败不影响原文阅读。
- 首次云端上传需用户确认，按用户授权决定后续是否自动开始 MinerU。
- MinerU 托管任务完成后才能下载完整结构和图表资产；界面显示实际阶段和服务提供的进度，不伪造中间结果。
- 解析结果和所有资产持久化完成后才发布；下载失败按既有任务恢复，不重复上传。

## 按需理解

1. 单击原文段落只选择内容，不调用模型。
2. 用户点击“翻译”时生成整段译文；划选句子时只翻译实际选中的原文。
3. 双击段落并行生成翻译与解释，两项独立显示进度和结果，一项失败不取消另一项。
4. 摘要与作用、解释、图表理解、词汇精选、论文概览和问答都由用户主动发起。
5. 词汇以完整当前段落为来源，用户主动添加到跨论文个人单词表。
6. 已完成且适用的缓存可以复用，不因为打开论文而产生新模型请求。
7. 切换段落、论文或服务配置会取消当前请求并丢弃晚到结果。

结果只显示在研究助手，不在 PDF 原件上插入中文段落。流式过程独立于正文解析，最终结构校验成功后才能缓存；模型配置未就绪时提供中文配置入口，不生成伪译文。

## 状态与入口

顶部状态条保留原件和解析状态，例如：

```text
原文阅读 · 可阅读   段落定位 · 已解析 60% 页面
```

只保留与实际任务对应的上传、解析、下载和失败重试。不再显示中文预览、后台翻译段数、预译队列或暂停、继续预译按钮；助手中的“导入与翻译”区域已移除。

排队、页面解析、结果转换和下载分别显示真实阶段；上传和下载不虚构百分比。定位就绪提示 4 秒后消失，也可以手动关闭。下载中断时继续已有批次，需要重新上传时按原有授权设置确认。

`PaperPipelineState` 只描述原件准备和 MinerU：文档身份、内容来源、阶段、解析进度、解析消息与错误。用户主动分析继续使用独立的 `pendingAction`、请求身份、流式输出和错误状态。

## 兼容与恢复

- 原始文件、文献库、解析资产、任务、单词表和历史分析缓存不清空。
- 重启后恢复基础正文整理与 MinerU 任务，不恢复翻译队列。
- 已完成的 MinerU 结果直接使用，不额外调用模型。
- 旧版本的译文记录可以继续留在缓存；没有适用结果时等待用户主动生成。

## 验证

自动测试覆盖导入 PDF、正文整理重试、MinerU 完成与恢复期间零模型请求，以及按需翻译、并行解释、取消、原文划选和单词表行为。

`npm run check` 验证凭据扫描、单元测试、TypeScript 与前端构建。`npm run test:paragraph-vocabulary:e2e` 使用隔离用户目录、合成 PDF 和模拟 SSE 检查真实桌面导入、解析恢复、按需译文、Markdown 和单词表，不使用真实服务密钥或用户论文。
